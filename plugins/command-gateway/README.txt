patchkit —— 随包的「指令前置」补丁表
=====================================

这里装的不是前置插件本体，只是它的**补丁表**：patch.mjs（补丁引擎 + 18 个块的锚点）
和 patches/（18 段注入核心的代码）。它只有约 45KB。

为什么需要它
------------
本插件的管理面板要嵌进 QQ Agent「设置」的左栏，那条通道是「指令前置」给核心文件
打补丁提供的。而**光看版本号判不出"这份前置在这台核心上到底能不能用"**：
1.3.1 在 0.4.0 上没问题，在 0.4.4 / 京玉版上锚点全废；1.4.3 在 0.4.4 上好、在京玉版上挂 2 块。

实测（npx 探测，只读不写盘）：

    补丁表                        0.4.4      京玉版     0.3.1 写法
    1.3.1   (PATCH_VERSION 3)    17/18      15/18      15/18
    1.4.3   (PATCH_VERSION 5)    18/18      16/18      16/18
    jy-1.4.3(PATCH_VERSION 6)    18/18      18/18      18/18   ← 包里的就是这份

安装脚本怎么用它
----------------
1. 先拿**已装**的那份 patch.mjs 探测本机核心；
2. 全都 "可打 / 已打" → 说明这台机器上的前置是好的，直接装插件，一个字节都不动；
3. 只要有块"冲突 / 缺符号 / 文件没了" → 就地移植：把已装目录里的 patch.mjs + patches/
   先整份备份到 <核心>\sticker-admin-backup\<时间戳>\ 下，再把这套覆盖过去，然后复检；
   复检不过就**原样回滚**。
4. 移植后 plugin.json 的 id/version 一概不动（还是显示 1.3.1），只换了补丁表。

为什么保留 1.3.1 的版本号
------------------------
换掉 plugin.json 就等于换了一个插件 id，控制台的插件列表会多出一个"新插件"、
配置段也会分裂。只换补丁表，插件还是那一个，配置、权限、指令表全都接着用。

来源
----
[京玉适配版] [前置插件]可用于制作各种指令v1.4.3-Beta.zip（id=jy-command-gateway-1.4.3-Beta，version=jy-1.4.3-Beta），逐文件 sha256 记在 KIT.json 的 files 里，
安装脚本落地前会按它对一遍。

注意
----
· 补丁是在**插件启用/软件启动时**打到核心上的，所以移植完要重启 QQ Agent
  （或者把前置在插件页里关一下再打开），补丁才会真正生效。
· 停用「指令前置」会按标记把补丁摘掉，也要重启才生效 —— 这是前置本身的设计，不是这里加的。
