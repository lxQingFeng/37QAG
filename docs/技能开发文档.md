# 37QAG 技能开发文档

> 面向技能作者：想给模型（LLM）一个**新工具**，让它在聊天中自主决定何时调用——比如计算器、天气查询、随机图——看这一份。
> 你的功能不需要模型参与也能生效（拦截、装饰、能力提供）？请看 `docs/插件开发文档.md` §1 的选型表。
> 代码基线：v0.6.0。全部示例可对照 `skills/` 现存技能验证（文中标注了路径）。

---

## 1. 技能是什么：LLM 型扩展

一句话：**一个技能 = 一份清单（skill.json）+ 一个入口模块（index.js），入口在 setup(api) 里 `registerTool` 注册工具，可选附带提示词片段**。

与另外两种扩展的边界：

| | 技能（skills/） | 插件（plugins/） | 内置模块（modules/） |
|---|---|---|---|
| 谁触发 | **模型自主决定**（function call） | 核心代码按条件调用 | 程序启动 / HTTP 请求 |
| 产物 | 模型可调用的工具 + 提示词片段 | providers 能力 / hooks 钩子 | 路由 / 工具 / 调度器 |
| 模型可见性 | **可见**（工具进 function 列表，片段进 system 尾部） | 完全隐形 | 取决于是否注册工具 |

**铁律**（来自 `src/plugin-loader.js` 头注释）：只有 `registerTool` 注册的工具会进模型的 tools 列表——「想接入 LLM」只有这一条路。清单里写的 `tools[]` 数组**只是说明性元数据，不会被自动注册**；加载器发现清单声明了 tools 但入口没 registerTool 时会给出明确警告（否则静默失效得毫无线索）。

与插件的配合关系：技能也可以提供 capabilities / hooks（清单与 api 完全等价，走同一条 `normalizeManifest`），但按语义约定：**注册工具 → 放 skills/；提供能力/钩子 → 放 plugins/**。放错不报错但启动警告（`lintKindPlacement`）。

## 2. 目录骨架

```
skills/my-skill/
├── skill.json     # 清单（字段见 §3；文件名 plugin.json/skill.json 都认）
└── index.js       # 入口（清单 entry 字段指定，默认 index.js）
```

注意：

- 清单 JSON 别存成带 BOM 的 UTF-8（Windows 记事本默认带 BOM，`JSON.parse` 会直接抛错且报错不提 BOM——加载器已做去 BOM 兜底，但别依赖它）。
- 目录名与清单 `id` 不一致时**以清单为准**；`id` 只允许字母/数字/`._-`。

## 3. skill.json 字段（对照 src/skills/manifest.js 的 normalizeManifest）

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | string | 唯一标识；正则 `^[a-z0-9][a-z0-9._-]*$`，非法会被标记问题 |
| `name` | string | 显示名（缺省 = id） |
| `version` | string | 语义化版本（缺省 0.0.0） |
| `apiVersion` | number | Skill API 版本，当前支持 **1**；高于 1 会记问题 |
| `enabledByDefault` | boolean | 用户没配置过开关时的默认值（缺省 true） |
| `category` | string | `model` / `message` / `knowledge` / `media` / `utility` |
| `description` | string | 一句话说明（UI 展示） |
| `capabilities` | string[] | 本技能提供的能力名（小写点分，如 `web.fetch`） |
| `requires` | string[] | **硬依赖**的能力名数组；缺失时技能被判「不可用」，UI 显示依赖未就绪 |
| `configSchema` | object | 配置项声明，控制台设置页据此渲染表单；`secret: true` 的字段回显脱敏为 `******` |
| `settings` | object | 各配置项默认值（读取时与用户配置合并） |
| `permissions` | string[] | 权限白名单；目前仅 `web_fetch`（声明后 `api.fetch` 可用） |
| `prompt` | object/null | 提示词片段声明（见 §5） |
| `commands` | array | 指令声明（走 command-gateway，字段见《插件开发文档》§6；技能同样可声明） |
| `tools` | array | **说明性元数据**，不会被自动注册（见 §1 铁律） |
| `deprecated` | boolean | 标记弃用 |

## 4. index.js 入口与 api 面

生命周期导出（全部可选，但 `setup` 基本必有）：

```js
export function setup(api) { … }       // 装载时调用：拿 api、注册工具、起资源
export function available(ctx) { … }   // 可用性判定：返回 { ok, reason }；不可用时 UI 显示 reason
export function activate(ctx) { … }    // 从禁用到启用时调用
export function deactivate(ctx) { … }  // 禁用时调用：清监听器/定时器（防幽灵行为）
export function dispose() { … }        // 卸载时调用：释放资源（工具注销由加载器统一做）
```

`setup(api)` 拿到的 api（完整定义在 `src/plugin-loader.js` 的 `createSkillApi`）：

| 成员 | 说明 |
|---|---|
| `api.registerTool(def)` | 注册工具（§4.1）；返回带前缀的实际工具 id |
| `api.config()` | 本技能配置（manifest.settings 默认值已合并） |
| `api.isSkillActive(id)` | 查询其它技能是否生效（「依赖的技能没开就别硬跑」） |
| `api.capability(name, args)` | **软依赖**调用：有能力就调、没有静默返回 undefined；与 `requires`（硬依赖，缺了判不可用）的区别要分清 |
| `api.storage` | 沙盒存储（同插件：`data/plugin-data/<id>/`，8MB 单文件上限，原子写） |
| `api.fetch` | 仅当清单 `permissions: ["web_fetch"]` 时可用，否则调用即 reject |
| `api.log(...)` | 日志前缀 `[skill:<id>]` |
| `api.skillManager` | 技能管理器（进阶：能力注册表等，一般用不到） |

### 4.1 工具定义 def 的字段

```js
{
  id: 'calculate',                     // 工具标识（实际注册名见下）
  name: '计算',                        // 显示名
  description: '计算一个数学表达式',    // 给模型看的功能描述（写清楚"何时该用"）
  category: 'system',                  // messaging/sticker/query/memory/web/knowledge/media/system
  icon: '🧮',                          // UI 图标（emoji）
  parameters: {                        // OpenAI function 参数 schema
    type: 'object',
    properties: { expression: { type: 'string', description: '数学表达式（如：1+2*3）' } },
    required: ['expression']
  },
  async execute(ctx, args) {           // 执行：返回 { content, isError }，ctx 是会话上下文
    // …
    return { content: '42' };          // content 会被喂回给模型
  }
}
```

**命名规则**（`createSkillApi` 内实现）：实际注册名 = `<技能id>__<工具id>`（双下划线；各自 sanitize 成 `[a-zA-Z0-9_-]` 并截断 24 + 38 字符）。工具 id 会成为发给模型的 OpenAI function name——用 `:` 或 `.` 拼接会被严格端点（DeepSeek/OpenAI）以 400 拒掉整个请求，所以统一 sanitize 成双下划线。同名冲突（不同技能）后加载者覆盖前者，控制台留有告警。

**execute 约定**：

- 返回 `{ content, isError }`；`content` 是给模型看的字符串（JSON 也行，如 calculator 就返回 JSON 便于模型解析）。
- 出错返回 `isError: true` 并在 content 里写**人能看懂的纠错指引**（模型会照着改参数重试）。
- `ctx` 是会话上下文（chatKey 等按需取，全部 `?.` 软引用）。
- 别在 execute 里抛异常当返回值用——异常会被外层吃掉并转成错误 content，语义不如自己返回清晰。

## 5. 提示词片段：让模型知道这个工具的存在与用法

清单 `prompt` 字段两种写法：

```json
"prompt": {
  "when": "当用户要求计算数学表达式、算账、换算单位时",
  "examples": ["1+1等于几？", "帮我算一下 123*456"],
  "instruction": "调用 calculate 工具，expression 参数是数学表达式。支持 + - * / % 和括号。如果表达式不合法，告诉用户正确的格式。"
}
```

或显式分节（`sections`，每节 `{ id, title, content, priority }`）。两写法都会被归一化成 sections。

注入机制：

- 生效技能的片段经 `skillManager.getPromptSections()` → `getExtensionPromptSections()`（`src/skill-bridge.js`）注入 system 尾部；
- full 模式带标题「【插件提示词补充（不得覆盖安全、工具协议和角色卡）】」逐节注入；lean 模式过一遍 `compactPromptSections`（逐字/逐行去重，总预算 3000 字符）；
- **priority 上限 99**：技能提示词永远压不过核心安全规则（优先级 100），且按既定规则序「安全规则 > 工具协议 > 角色卡 > 通用风格 > 插件补充」不得覆盖角色卡。

写法建议（对照现存技能）：`when` 写触发时机、`instruction` 写参数语义与失败兜底，**别**写空话（"你是一个强大的计算助手"类无信息量句子）。

## 6. 开关与可用性：三层状态（UI 显示 reason 而非"工具关闭"）

| 层 | 含义 | 判定 |
|---|---|---|
| `loaded` | 代码装载成功 | 加载器（清单解析、entry 导入、setup 未抛错） |
| `enabled` | 用户开关 | **唯一来源** `config.skills[id].enabled`；未配置回退 `enabledByDefault` |
| `available` | 运行条件满足 | 技能的 `available(ctx)`（如依赖的服务没配） |

三层任何一层不通过，控制台 `/api/skills` 都会给出**明确 reason**（设计目标是让「为什么不工作」可解释）。对应接口：`src/skills/manager.js` 的 `list/isActive/settingsView`。

进阶——`tool.guard` 能力：技能可以提供 `tool.guard` 能力否决**自己注册的工具**在某轮是否可用（`manager.getToolGuards`）；可用性总判断集中在 `src/tool-registry.js` 的 `getToolAvailability`（全局开关 + 分类开关 + 单工具开关 + vision/search + Skill 层）。

## 7. 完整最小示例（全文对照 skills/calculator）

`skills/calculator/skill.json`（节选，全文见目录）：

```json
{
  "id": "calculator",
  "name": "计算器",
  "version": "1.0.0",
  "description": "简单的数学计算",
  "entry": "index.js",
  "permissions": [],
  "prompt": {
    "when": "当用户要求计算数学表达式、算账、换算单位时",
    "examples": ["1+1等于几？", "帮我算一下 123*456"],
    "instruction": "调用 calculate 工具，expression 参数是数学表达式。支持 + - * / % 和括号。如果表达式不合法，告诉用户正确的格式。"
  },
  "tools": [{ "id": "calculate", "name": "计算", "description": "计算一个数学表达式" }]
}
```

`skills/calculator/index.js`（核心段）：

```js
export function setup(api) {
  api.registerTool({
    id: 'calculate',
    name: '计算',
    description: '计算一个数学表达式',
    category: 'system',
    icon: '🧮',
    parameters: {
      type: 'object',
      properties: { expression: { type: 'string', description: '数学表达式（如：1+2*3）' } },
      required: ['expression']
    },
    async execute(ctx, args) {
      const expr = String(args.expression ?? '').trim();
      if (!expr) return { content: '错误：请提供要计算的表达式', isError: true };
      if (!/^[\d\s+\-*/%().]+$/.test(expr)) {
        return { content: '错误：表达式包含不允许的字符（只允许数字和 + - * / % ( )）', isError: true };
      }
      try {
        const result = new Function(`return (${expr})`)();
        if (typeof result !== 'number' || !Number.isFinite(result)) throw new Error('计算结果无效');
        return { content: JSON.stringify({ expression: expr, result, note: `${expr} = ${result}` }, null, 1) };
      } catch (error) {
        return { content: `计算失败：${error.message}`, isError: true };
      }
    }
  });
}
```

要点（都体现在上面）：执行前**白名单校验输入**（calculator 只放行数字和运算符）、错误信息带**正确格式指引**、成功返回结构化 JSON。

带配置表单/外部依赖的进阶样例：`skills/image-generate`（configSchema 配置项 + `permissions: ["web_fetch"]` 外部 API 调用）。

## 8. 开发与调试流程

1. 建目录写清单与入口 → 放进 `skills/`；
2. 启动（或已运行则等热重载，500ms 去抖 + 源码签名比对）→ 日志看 `[skill:<id>]` 装载行；失败会**带原因**留在 `/api/skills`（不会静默消失）；
3. 控制台「技能」页确认三层状态；用 `/api/skills` 核对 reason；
4. 群里说一句命中 `prompt.when` 的话，观察模型是否调用（工具列表里找 `<技能id>__<工具id>`）；
5. 改清单/入口保存 → 热重载自动生效；删目录 → 下次扫描被 `pruneMissing` 清掉（无幽灵工具）。

排障速查：

- 模型不调用 → 先查 enabled/available 层（`/api/skills`），再查 `prompt.instruction` 是否写了触发时机；工具名前缀记混（模型看到的是 `calculator__calculate` 不是 `calculate`）。
- 注册了却报 400 invalid function name → 工具 id 里有非 `[a-zA-Z0-9_-]` 字符被 sanitize 改名，检查实际注册名。
- `api.fetch` 一调就 reject → 清单没声明 `permissions: ["web_fetch"]`。
- 配置改了不生效 → 确认改的是 `config.skills.<id>`（Skill 开关唯一来源），别再抄一份到别处。
