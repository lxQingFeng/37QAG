> 面向插件作者：想在**不碰核心源码**的前提下改变/增强机器人行为（发消息前拦一道、给 LLM 请求加参数、提供一项被核心调用的能力、注册一条 `/指令`）——看这一份。

## 1. 先选对扩展类型（最重要的一步）

| | `plugins/`（确定性型） | `skills/`（LLM 型） | `modules/`（内置功能模块） |
|---|---|---|---|
| 面向 | 核心代码 | 模型（LLM） | 核心代码 + 控制台 |
| 触发方式 | 满足条件**必然执行**，不经过 LLM | 模型自己决定调不调 | 随程序启动/HTTP 请求 |
| 提供物 | `providers`（能力）/ `hooks`（钩子）/ 指令 | `registerTool` 注册的工具 + 提示词片段 | 路由/工具/事件订阅/调度器 |
| 典型 | 禁言状态、图片兼容、思考适配 | 计算器、天气查询、随机图 | 主题、语音、疯四、API 情报 |

**判断口诀**：你的功能「模型不参与也必须生效」→ `plugins/`；「要让模型知道并自主调用」→ `skills/`；「要挂 HTTP 路由或后台定时器」→ `modules/`。

放错目录不会报错，但启动日志会警告（`src/plugin-loader.js` 的 `lintKindPlacement`）：

- 只有 providers 的模块放进 `skills/` →「模型看不到它，功能永远不会被触发」；
- 只有工具的模块放进 `plugins/` →「能用，但语义混乱」。

清单文件名两目录等价（`plugin.json` / `skill.json` 都认，走同一条 `normalizeManifest`，见 `src/skills/manifest.js`）；区别只在语义目录。

> **门控边界（jev 级联，2026-09-27）**：`api.toolGate`（rules/jev/jev2 档）裁的是**技能的工具与技能提示词段**——按 `skill.json` 的 `gateCategory` 类别判定。`plugins/` 的 providers/hooks/指令走确定性执行通道，**不参与门控、恒常驻**，插件作者无需关心该配置（`off` 与 `rules` 档对插件行为零差异）。

## 2. 插件骨架（最小结构）

```
plugins/my-plugin/
├── plugin.json     # 清单（字段见 §3）
└── index.js        # 入口：导出生命周期 + providers/hooks
```

`index.js` 的完整导出面（全部可选，按需导出）：

```js
// 生命周期：register → (activate) → … → deactivate → dispose
export function setup(api) {}        // 装载时调用：拿 api、做初始化（最常用）
export function activate(ctx) {}     // 从禁用恢复时调用（补监听器/定时器）
export function deactivate(ctx) {}   // 被禁用时调用（清监听器/定时器）
export function dispose() {}         // 卸载/热重载时调用（清资源；工具会由加载器批量注销）

export function available(ctx) {     // 可用性自检：返回 { ok, reason }
  return { ok: true };               // 返回 ok:false 时 UI 会展示 reason，核心跳过它
}

export const providers = { };        // 能力提供者（§4）
export const hooks = { };            // 核心链路钩子（§5）
export const internals = { };        // 暴露给测试的内部函数（可选，惯例名）
```

生命周期真实性是硬要求：**禁用一定走 `deactivate`**，不能只在前端取消勾选，否则会留下幽灵监听器（`src/skills/manager.js` 头注释三条规则之一）。

> 入口名兼容说明（如实标注）：加载器对入口函数**同时认 `setup` 与 `register`**（`src/plugin-loader.js:465-466`——`setup` 优先，`register` 是给老代码留的兜底别名，两者等价）。现存 16 个插件均用规范名 `setup`；`skills/` 侧有 3 个老技能（calculator / text-tools / weather-query）仍在用 `register`。新代码一律写 `setup`。

## 3. plugin.json 字段速查

以 `plugins/ban-state/plugin.json` 为实例（可对照原文）：

```json
{
  "id": "ban-state",                 // 唯一标识（^[a-z0-9][a-z0-9._-]*$，不符则该清单拒载）
  "name": "群禁言状态",
  "version": "1.0.0",
  "apiVersion": 1,                   // 高于当前支持版会记 problem
  "category": "utility",             // model | message | knowledge | media | utility
  "description": "一句话说明（UI 展示）",
  "author": "QQ Agent",
  "enabledByDefault": true,          // 用户没配置过时的默认开关
  "capabilities": ["chat.ban-state"],// 本插件提供的能力名（小写点分）
  "requires": [],                    // 硬依赖的能力名：缺了 → 插件判“不可用”，UI 显示“依赖未就绪”
  "settings": { "skipRunWhenMuted": true },          // 配置默认值（api.config() 能读到）
  "configSchema": {                  // 声明式配置表单（UI 据此渲染；secret 字段回显 '******'）
    "skipRunWhenMuted": { "type": "boolean", "label": "被禁言时不发起运行", "description": "…" }
  },
  "permissions": ["web_fetch"],      // 只有声明了才拿得到 api.fetch
  "prompt": null                     // 提示词片段（插件一般不用，见技能文档）
}
```

规则细节出处：`src/skills/manifest.js` 的 `normalizeManifest`（弱校验、单条坏不拖垮整份清单）。

## 4. providers：以「能力名」被核心消费

核心**按能力名取用，绝不 import 具体插件**（`src/skills/manager.js` 的“能力优先于名字”规则）。因此替换一个实现（比如把 ban-state 换成自己的版本）不需要改核心。

提供者写法（摘自 `plugins/ban-state/index.js`）：

```js
export const providers = {
  'chat.ban-state': ({ chatKey, action = 'check', durationSec = 0 } = {}) => {
    // 返回普通对象；调用方拿到什么完全由你们两个约定
    return { muted: isMuted(chatKey), known: true, skipRun: true };
  }
};
```

核心侧消费（对照 `src/orchestrator.js:811`）：

```js
for (const p of skillManager.getCapabilityProviders('chat.ban-state', { chatKey, kind: 'group' })) {
  const r = p.fn({ chatKey });        // 遍历生效中的提供者（约定：同类能力一个提供者）
}
```

插件内部消费其它插件的能力用**软依赖**（`api.capability('主人识别能力名')`：有则增强、无则降级）；跨插件的**硬依赖**写进 `requires`。两者区别详见 `src/plugin-loader.js` 的 `createSkillApi` 注释。

常用既有能力名（小写点分；同类能力一个提供者）：`chat.ban-state`、`llm.request-params`（给 LLM 请求补参数，thinking-adapters 在用）、`llm.response`、`llm.retry-advisor`、`tool.guard`（工具可用性否决）。

## 5. hooks：核心链路上的五个拦截/观察点

在 `src/skill-bridge.js` 发射，经 `skillManager.runHook` 执行：

| 钩子 | 时机 | 典型用途 | 可拦截 |
|---|---|---|---|
| `before-context` | 组装提示词之前（每触发轮） | 情绪/睡眠状态、上下文裁剪 | 否 |
| `before-llm-messages` | 请求模型之前 | 注入会话记忆片段 | 否 |
| `after-response` | 模型回复之后 | 统计、审计 | 否 |
| `before-tool` | 每次工具执行前 | 安全拦截 | **是**：任一钩子返回 `{ block: true, reason }` 即中止该次工具调用 |
| `after-tool` | 工具执行后 | 结果加工、审计 | 否 |

`before-tool` 的载荷形状（对照 `src/orchestrator.js` 的 `hookBeforeTool` 调用处）：`{ toolName, argsRaw, session, chatKey, kind, chatId }`，其中 `argsRaw` 是工具参数的 **JSON 字符串**，需要自己 `JSON.parse`。

写法（摘自 `plugins/sleep-mood/index.js` 的注释约定）：

```js
export const hooks = {
  'before-context'(ctx = {}) {           // ⚠️ 钩子 5 秒超时，禁止网络请求与重副作用
    const s0 = settings();
    // …本地正则与文件读写
  },
  'before-tool'(payload) {
    if (payload?.toolName !== 'send_message') return;
    const args = JSON.parse(payload?.argsRaw || '{}');
    if (isBlocked(args?.messages)) {
      return { block: true, reason: '复读护栏：命中拦截词' };   // 拦截语义
    }
  }
};
```

约定：单个钩子卡死不能拖垮整轮对话（超时见 `manager.js` 的 `DEFAULT_HOOK_TIMEOUT_MS = 5000`）；所有钩子异常被吞、只记日志。

## 6. 指令声明：commands[]（配合 command-gateway）

想让用户在群里打 `/禁言 @张三` 直接触发你的逻辑（不烧 LLM），在清单里声明 `commands`，由 `plugins/command-gateway` 在会话前拦截并路由到你的 `capability`（归一化实现：`src/skills/manifest.js` 的 `normalizeCommand`）。

```json
"commands": [{
  "id": "mute",                     // 稳定标识（缺省 = word）；用户改指令词不影响它
  "word": "禁言",                    // 默认指令词（不含 / 前缀）
  "aliases": ["jy"],                // 默认别名（可省）
  "capability": "command.mute",     // 执行能力名；缺省 = command.<插件id>
  "description": "在群里禁言某人",
  "argsHint": "@用户 [时间=30分钟]",
  "examples": ["/禁言 @张三"],        // 帮助列表展示，最多 5 条
  "permission": 100000,             // 权限等级；缺省 1
  "timeoutMs": 15000,               // 最长执行时间；缺省 30s
  "passthrough": "args"             // 执行后是否放行给 LLM：original/prefix/args 或缺省不放行
}]
```

实例全文：`plugins/command-gateway/plugin.json`（当前内置 8 条指令：禁言/解禁等）。执行体就是同名的 providers 项（`'command.mute': (args) => …`）。

## 7. api 面（setup(api) 拿到的对象）

完整定义在 `src/plugin-loader.js` 的 `createSkillApi`：

| 成员 | 用途 |
|---|---|
| `api.id` | 本插件 id（由加载器告知，别在代码里硬编码） |
| `api.config()` | 本插件配置（manifest.settings 默认值已合并；用户在设置页改） |
| `api.storage` | 数据沙盒：`data/plugin-data/<id>/`（§8） |
| `api.capability(name, args)` | 软依赖调用其它能力；`api.hasCapability(name)` 只查询 |
| `api.isSkillActive(id)` | 查询其它扩展是否生效 |
| `api.registerTool(def)` | 注册 LLM 工具（插件里也能用；命名与细节见技能文档） |
| `api.fetch` | 仅当 `permissions: ["web_fetch"]` 时为真 fetch，否则恒 reject |
| `api.log/warn/error` | 带前缀 `[skill:<id>]` 的日志 |
| `api.utils.sleep / safeJsonParse` | 小工具 |

## 8. 数据存储：api.storage（隔离 + 防呆）

实现：`src/plugin-loader.js` 的 `createPluginStorage`。目录固定在 `data/plugin-data/<插件id>/`（旧 `command_data/<id>/` 会被 `paths.migrateLegacyLayout` 自动搬过来）。

```js
api.storage.writeJson('state.json', { runs: 3 });   // 原子写（tmp + rename），单文件 8MB 上限
const s = api.storage.readJson('state.json', { runs: 0 });   // 读不到返回 fallback，不抛错
api.storage.read('notes.txt', null);                // 读文本
api.storage.exists('state.json');
api.storage.dir;                                    // 目录绝对路径（想用自己的库直接读写时）
```

**禁止**把插件数据写到 `data/plugin-data/` 之外（备份与隔离都会失效）。实例：`plugins/health-system/index.js`（迁移到 plugin-data 的完整案例，配套测试 `test/stability-fixes-test.mjs`）。

## 9. 热重载与状态可见性

- `plugins/` 与 `skills/` 双目录 `fs.watch` 监听，改动 500ms 去抖后重载（`plugin-loader.js` 尾部 `startExtensionWatch`）。编辑清单或入口即可热生效，**不用重启**。
- 装载失败不会“消失”：失败条目以 `loadError` 注册进注册表，`/api/skills` 与控制台都能看到「加载失败 + 原因」（此前直接 return 的行为已废弃）。
- 删目录后 `pruneMissing` 会把注册表对齐磁盘（不留幽灵工具/能力）。
- 开关唯一来源：`data/config.json` 的 `skills.<id>.enabled`。三层状态 `loaded / enabled / available` 各有 reason，UI 直接展示（`manager.js` 设计要点）。
- 状态查询接口：控制台设置页，或 `GET /api/skills`（返回 `listExtensionStatus()`）。

## 10. 最小可运行示例（可直接拷贝）

`plugins/echo-guard/`——示例：有人让机器人复读「启动」两个字时拦截，其余正常；附带一个计数器演示 storage。

`plugin.json`：

```json
{
  "id": "echo-guard",
  "name": "复读护栏（示例）",
  "version": "1.0.0",
  "apiVersion": 1,
  "category": "utility",
  "description": "示例插件：拦截要复读敏感词的消息，其余放行；带 storage 计数。",
  "author": "you",
  "enabledByDefault": true,
  "capabilities": [],
  "requires": [],
  "settings": { "blockedWords": "启动,重启" },
  "configSchema": {
    "blockedWords": { "type": "string", "label": "拦截词（逗号分隔）" }
  },
  "permissions": []
}
```

`index.js`：

```js
let api = null;

export function setup(a) { api = a; }

export function available() { return { ok: true, reason: '' }; }

export const hooks = {
  'before-tool'(payload) {
    if (payload?.toolName !== 'send_message') return;
    // argsRaw 是工具参数的 JSON 字符串（对照 orchestrator 的 hookBeforeTool 调用处）
    let messages;
    try { messages = JSON.parse(payload?.argsRaw || '{}').messages; } catch { return; }
    const texts = Array.isArray(messages) ? messages : [messages];
    const words = String(api?.config()?.blockedWords || '启动,重启').split(',').map((w) => w.trim()).filter(Boolean);
    const hit = texts.some((t) => words.some((w) => String(t).includes(w)));
    if (!hit) return;
    const n = Number(api.storage.readJson('count.json', { blocked: 0 }).blocked) + 1;
    api.storage.writeJson('count.json', { blocked: n });
    api.log(`已拦截第 ${n} 次`);
    return { block: true, reason: '复读护栏：命中拦截词' };
  }
};
```

> before-tool 的载荷以 §5 表下方的形状说明为准（`toolName` + `argsRaw` JSON 字符串）；想精确对齐其它字段，先在钩子里 `api.log(JSON.stringify(payload))` 打印一次再写判断。

放置与验证四步：① 目录丢进 `plugins/` → ② 看启动日志出现 `[skill:echo-guard]` → ③ 群里让 bot 复读「启动」观察拦截 → ④ 改 `index.js` 任意一行保存，5 秒内热重载生效。

## 11. 从旧「改核心源码 + 重启」迁移到新体系

旧模式的三个代价：升级冲突（每次拉新版都要重打补丁）、无隔离（改坏一处全崩）、无可见性（出问题只能翻源码。新体系对应物映射：

| 你以前改的地方 | 现在的写法 |
|---|---|
| `orchestrator.js` 里加判定/短路 | `hooks['before-context']`（每轮必经）或提供 `chat.*` 能力 |
| `llm.js` 里改请求参数/方言 | `capabilities: ['llm.request-params']`（参考 `plugins/thinking-adapters`） |
| `sender.js` 里改发送行为 | `before-tool` 拦 `send_message` / 订阅 `message.sent` 事件做审计 |
| `app.js` 里加 HTTP 路由 | 放 `modules/` 用 `api.registerRoute`（内置模块走这条路，见 `modules/api-news`） |
| 手写的 `/指令` 补丁 | 清单声明 `commands[]`（`command-gateway` 统一拦截执行） |
| 全局可变对象存状态 | `api.storage`（`data/plugin-data/<id>/`） |

迁移步骤（每步可独立验证）：

1. 把补丁逻辑整理成「输入 → 判定 → 动作」三段，确认它插在链路的哪个环节（对照 §5 钩子表）；
2. 建目录写 `plugin.json`（`capabilities` 先留空）+ `index.js` 空 `setup`，确认能装载（日志 + `/api/skills`）；
3. 把逻辑搬进对应 `hooks`/`providers`，状态搬进 `api.storage`；
4. 指令类补丁改 `commands[]` 声明；
5. 删掉核心源码里的改动，跑 `npm test`（188 基线全绿）+ 群里实测一遍。

## 12. 调试速查

- 看装载：启动日志 `[skill]` 前缀行；失败条目带原因，不会静默消失。
- 看状态：`GET /api/skills`（三层状态 + reason）。
- 看钩子执行：钩子内 `api.log(...)`；5 秒超时是兜底不是日常。
- 看事件订阅统计：`src/event-bus.js` 的 `listenerStats()`（测试/诊断用）。
- 热重载不生效时：确认改的是 `plugins/`（或 `skills/`）目录内文件；`data/plugin-data` 的改动不会触发重载（那不是源码）。
- 参考 `plugins/ban-state`（能力+配置）、`plugins/sleep-mood`（钩子全家桶）、`plugins/health-system`（storage 迁移）、`plugins/command-gateway`（指令声明）。
