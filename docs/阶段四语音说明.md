# 37QAG 阶段四·语音能力说明（v0.6.0）

> 依据：群内《37QAG免费TTS-STT选型调研报告.md》推荐档（云端 STT=硅基流动 SenseVoiceSmall / TTS=edge-tts；本地档 sherpa-onnx+SenseVoice / Kokoro 纳入 channel 体系）。
> 结果：**117/117 测试全绿**（原 101 + 语音 16 项），模块化挂载于阶段二 modules/ 体系。

---

## 一、模块结构（modules/voice/）

```
modules/voice/
├── module.json     # 清单（optionalDependencies: silk-wasm / msedge-tts / sherpa-onnx-node）
├── index.js        # 挂载：media.transcribe 能力 + send_voice 工具 + message.sent 事件 + 2 条路由
├── audio.js        # 音频层：QQ 语音获取（URL/file/base64）+ silk 解码（可选）+ WAV 编解码
├── stt.js          # STT 引擎：channel 化 + OpenAI 兼容云端调用 + 本地 CLI + 降级链
└── tts.js          # TTS 引擎：edge-tts（可选依赖）+ 本地 Kokoro + 降级链
```

## 二、数据流

**收语音（STT）**：`record 段 → fetchRecordAsWav（①get_record 协议端转码 → ②silk-wasm 本地解码）→ transcribeWav（channel：云端硅基流动 multipart / 本地 CLI）→ "[语音]文字" 进聊天链路`
- onebot.js 转写链已升级为**遍历全部 media.transcribe provider**（voice 模块与老 speech-to-text 插件谁可用谁上，单个失败不挡下一个，25s 硬超时兜底）

**发语音（TTS）**：`文本 → synthesize（channel：edge-tts / Kokoro）→ toSendableRecord（silk-wasm 可用→wav→silk；否则 wav 直发由协议端转码）→ send_group_msg/send_private_msg record 段`
- **manual 模式**（默认）：模型经 `send_voice` 工具自主决定何时用语音（口语化内容语音、技术内容文字）
- **auto 模式**：订阅阶段二事件总线的 `message.sent` → 自动跟发语音（30s 冷却防工具+自动双发）

## 三、配置示例（data/config.json → voice 段，默认全关）

```jsonc
{
  "voice": {
    "stt": {
      "enabled": true,                          // 语音→文字
      "channel": "cloud",                       // cloud | local | auto（有 key→云，否则本地）
      "cloud": {
        "baseUrl": "https://api.siliconflow.cn/v1",
        "apiKey": "sk-xxx",                     // 免费注册 https://cloud.siliconflow.cn
        "model": "FunAudioLLM/SenseVoiceSmall"  // 平台永久免费模型
      },
      "local": { "engine": "sherpa-onnx", "modelPath": "", "cliPath": "", "language": "zh" },
      "fallback": "cloud-to-local"
    },
    "tts": {
      "enabled": true,
      "mode": "manual",                         // manual=模型自主 | auto=每条回复自动跟发
      "channel": "cloud",                       // cloud=edge-tts | local=Kokoro | auto
      "cloud": { "voice": "zh-CN-XiaoxiaoNeural", "rate": 0, "volume": 0, "pitch": 0 },
      "local": { "engine": "kokoro", "modelPath": "", "voice": "zf_xiaoxiao" },
      "encode": "auto",                         // auto=silk-wasm 可用则编码，否则直发
      "autoCooldownMs": 30000, "maxLength": 200
    }
  }
}
```

**可选依赖（运行时探测，不装则降级，不加 package.json 依赖）**：
- `npm i silk-wasm` → 启用本地 silk 编解码（STT 第二级 + TTS silk 编码）
- `npm i msedge-tts` → 启用云端 edge-tts
- sherpa-onnx（CLI/绑定）+ SenseVoice/Kokoro 模型 → 启用本地档

## 五、未覆盖事项（沙箱限制，如实说明）

1. **真实 QQ 语音收发联调**：沙箱无 QQ/OneBot 环境 —— record 段解析、get_record 转码、
   record 发送均为单测 mock + 实现层契约对齐（SnowLuma/NapCat 生态标准行为），需真机验证
2. **真实云端调用**：硅基流动需注册 key、微软 edge-tts 需外网 —— 均未实测，调用层按
   OpenAI 兼容/msedge-tts 官方 API 契约实现并 mock 测试
3. **silk-wasm/msedge-tts 实际编解码**：沙箱未安装（测试以「未装→正确降级」覆盖了降级路径）
4. **本地档（sherpa-onnx/Kokoro）**：模型管理器（下载/路径探测 UI）不在本轮，CLI 路线已实现
5. auto 模式与工具模式同开的冷却互斥已实现（30s），双开的实际效果未真机观察

## 六、设计要点（为什么这样落）

- **零新增依赖**：三个可选包全部运行时探测——保持项目 3 依赖轻量哲学，没装的路径都有明确降级
- **语音是增强不是必需**：任何失败（取音频/转写/合成/发送）都降级（[语音]占位 / 纯文字），
  绝不阻塞聊天主链路（与 onebot.js 既有铁律一致）
- **channel 理念贯通**：voice.stt/tts.channel 与阶段三 api.channel 同构（cloud/local/auto+一次性回退）
- **事件总线用例**：auto 模式直接消费阶段二 message.sent 事件——零侵入核心发送链路
