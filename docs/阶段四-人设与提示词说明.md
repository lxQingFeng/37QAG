## 一、提示词体系评估（如实结论）

### 检查范围
- system 侧：buildSystemPrompt 的 full（20 段规则 ~6000 字）/ lean（默认，~1700 字）/ compact / hype 四模式
- user 侧：buildUserPromptParts 的【会话身份】→【角色设定 roleText】→【过去状态】（锚定窗口）→【本次唤醒】→【运行态】五段
- 缓存保温链：system 稳定 + user stable 段 + 滑动窗口锚定（946-1436 行的专门工程）+ 显式缓存前缀
- 交叉：人设卡（roleText）× 系统规则段 × 工具白名单 × 技能 prompt 片段

### 结论：默认配置（lean）下无结构性冲突；发现 1 个真实风险点，已做针对性修复

| 检查项 | 结论 |
|---|---|
| 结构冲突 | **无**。full 与 lean 是显式模式切换；人设卡固定在 user stable 段（与「两种风格都不把 roleText 塞进 system」的注释一致）；compact 模式人设进 system 但属于该模式的定义本身 |
| 指令冲突 | **无**。小鲸鱼「大方承认 AI」vs 37/新三卡「坚持人类」是不同人设的相反设定，但 roleText 同一时刻只有一份生效，互不干扰；反 AI 味黑名单在人设卡与 system 段方向一致（双保险设计） |
| 冗余 | **full 模式下确有约 1/3 主题重叠**（人设卡 1300~6200 字 vs 系统规则 6000 字里工具/表情/记忆的重复教学），但默认 lean 已把系统侧砍到 1700 字，冗余可控；且人设卡位于 stable 前缀段，token 成本被 prompt cache 吸收。**判定：不需要硬优化**——改人设卡会破坏缓存前缀稳定性，收益不成比例 |
| 指令漂移 | **发现 1 个真实风险点**：system 段有 stripUnavailableToolRules 兜底「配置关掉的工具」，但 **user 侧的 roleText 从不过滤**——人设卡教模型用 send_sticker/web_search/memory_*，而配置白名单把工具撤掉时，模型无工具可调 → 用文字假装发（「打成括号形式，气笑了」事故的 user 侧变体） |

### 已做的针对性优化（唯一一处，不碰缓存链）
- `sanitizeRoleText()`（prompt.js 新导出）：roleText 进 user stable 段 / compact system 段前过一遍 stripUnavailableToolRules
- **缓存安全性**：过滤是纯确定性函数（同卡同白名单 → 恒定输出），stable 前缀稳定性不受影响；工具集变化（热重载/改白名单）本就会改变 tools 前缀，非本优化引入
- 语义边界（如实说明）：该过滤器管的是「白名单排除的工具」；完全不在核心工具枚举里的名字不在防御范围（模型无法调用未注册工具，风险敞口很小）

# 附：拟人化专项复查（2026-09-26，用户要求「提示词围绕 bot 拟人化，别硬写更不要乱写」）

## 结论：人设卡不动，只修系统侧 4 处硬编码身份句

5 张人设卡复查结论：**已经是行为级拟人写法**（具体行为规则、口癖与句长差异、反AI味黑名单、
防认领图、防自我解构、招牌句式、few-shot 示例），没有空泛「要像人」堆砌——按「别硬写」原则一律不改。

真问题（破坏人格一致性的一类）：**小鲸鱼卡是 AI 身份人设**（「以 AI 身份混在 QQ 群里」「被怀疑是 AI 时
大方承认：对，我是 DeepSeek」），而系统侧三处硬编码身份句与之正面冲突——选小鲸鱼时模型同时收到
相反指令，行为会摇摆，在群友眼里就是人设崩。改动（只换措辞，让位给角色卡，与既定优先级
「角色卡 > 通用风格」字面一致；人类卡的锚由卡自身声明 + 系统默认兜底，不丢）：

| 位置 | 旧（硬断言） | 新（让位给角色卡） |
|---|---|---|
| prompt.js full 开场 | 你是……普通人类群友 | 身份以【角色设定】那张卡为准：卡写人类或没写→普通人类群友；卡另写身份→照卡演 |
| prompt.js full qqSceneRules | 你跟 DeepSeek 没有关系 | 你跟 DeepSeek 是什么关系以角色卡为准：卡没写→别人的模型，别叫"我家" |
| prompt.js【身份收尾】(user prompt) | 别自曝AI/程序 | 身份话题按角色卡接（卡里是人类就别自曝AI/程序），别扯模型/训练/提示词 |
| prompt-cleaned.js lean 开场 | 你是……普通人类群友 | 同 full 的让位写法（精简版） |

## 检查过、判定不改的（如实说明）

- **反自我解构护栏全保留**：「我只是个AI/我没有感情」式塌台禁令、lean【身份】引导、subjectivity 原样——身份让位 ≠ 放开塌台。
- **looksLikeAiSelfClaim 运行时保险丝**（tools.js send_message 拦「我是AI」类自曝）：保留。小鲸鱼招牌句「我是 DeepSeek」不在拦截词表（AI/大模型/程序/助手/bot…），卡的玩法可用；拦的是各卡共同的自我解构腔。
- **自动配表情注入文案**（「表情由系统在你发完话后自动配」）：核实 orchestrator 确有 autoSticker 机制（冷却+意愿判定+自动配图），文案属实，不算乱写。
- **空泛「像人」指令**：仅 full 开场 1 处「发言自然得像人」，其余全是行为级规则（该说不说/节奏/主体性），无堆砌，不动。
- 已知小瑕疵（非拟人化问题，未改）：模板名「小鲸鱼（默认）」与出厂默认人设（37）不符，属历史标签；改动涉及 data/personas/ 播种一致性，留待用户决定。（✅ 2026-09-26 已解决：出厂默认人设改为小鲸鱼后名实相符，详见文末「附 2」。）

### 二、txt / md / json 人设导入（文件放入即生效）

`data/personas/` 文件层在 meta 头 `.md` 之外新增两种形态（`src/persona-files.js` `parsePersonaContent`，解析层与导入端点共用）：

| 格式 | 人设名来源 | 角色卡正文 |
|---|---|---|
| meta 头 `.md`（阶段四原始） | meta `name:` 行 | meta 注释块之后的全文 |
| **纯文本 `.md` / `.txt`** | 正文首个 `#` 一级标题（`# 角色卡：小白猫` → `小白猫`，去「角色卡：/人设：」类前缀）；无标题用文件名（去扩展名） | 整个文件内容 |
| **`.json`** | `{"id"?, "name"?, "text" | "roleText"}` 的 `name` | `text`（兼容 `roleText` 字段名，与 customPersonas 形态一致） |

用法（两条等价路径）：
1. **直接拖文件**：把 `.txt/.md/.json` 文件放进 `data/personas/`，重启或热重载后在控制台「人设模板」里出现（`builtin` 标记为非内置）。
2. **UI 导入**：设置 → 人设 → 「导入人设文件」按钮选文件，等价于拖文件（`POST /api/persona-templates/import` 先解析校验、再落盘 `data/personas/`，坏内容 400 不落盘）。

行为要点：
- **安全链与内置人设完全一致**：导入卡选入 `config.persona.roleText` 后，进提示词前同样过 `sanitizeRoleText`（不可用工具指引被裁掉，防「文字假装发」事故）。
- **坏文件/空文件跳过不崩**：空内容、坏 JSON 缺正文一律返回 null 并跳过（日志 `[personas] xxx 无法解析…已跳过`）。
- **与 .json 机制共存不冲突**：`.json` 文件独立解析为文件层人设；`config.customPersonas`（POST 添加的旧机制）原样保留，三层合并顺序不变（文件层 > 内置 > custom）。
- **同名（去扩展名）= 同一 id**：与「文件层覆盖内置」语义一致；UI 重复导入同名文件 = 覆盖更新。
- 删除导入的人设 = 删除对应文件（文件层人设不走 `custom_` 删除端点）。
