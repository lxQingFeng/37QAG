## 1. 一条消息的完整链路（先建立全局感）

```
QQ 服务器 ⇄ SnowLuma(OneBot)
                │ WebSocket
                ▼
         src/onebot.js        收/发协议层
                │
                ▼
      src/orchestrator.js     会话调度：唤醒判定→组上下文→跑 LLM 循环→执行工具→收尾
       │            │
       ▼            ▼
 src/prompt.js   src/llm.js   提示词组装（system/user 双轨）   OpenAI 兼容请求（多供应商/本地/云端）
       │            │
       ▼            ▼
  src/tools.js  （模型 function call）
       │
       ▼
   src/sender.js  分条发送、防复读、自动配表情 → 回到 onebot.js
```

控制台是独立的一条线：`src/app.js`（HTTP 服务，默认端口 **3210**）+ `ui/`（浏览器前端），桌面端由 Electron（`electron/main.js`）包同一套代码。headless 模式就是去掉 Electron 直接跑 `src/server.js`，浏览器访问控制台。

**核心链路的原则**：`orchestrator / llm / prompt / tools / sender / onebot / memory / sessions / config` 这条链不做拆分——所有「不改核心就做不了」的需求，都通过下面的扩展体系解决。

## 2. 架构总览（三套注册面 + 一条总线）

### 2.1 三个扩展目录，按「谁决定执行」分类

| 目录 | 类型 | 谁执行 | 典型形态 | 例子 |
|---|---|---|---|---|
| `modules/` | 内置功能模块 | 核心在启动/停止时调 `setup(api)`/`dispose(api)` | `module.json` + 路由/工具/事件注册 | `api-news`、`themes`、`voice`、`crazy-thursday` |
| `plugins/` | 确定性插件（16 个） | 核心按**能力名**取用，满足条件必然执行，**不经过 LLM** | `plugin.json` + `providers`/`hooks` 导出 | `ban-state`、`sleep-mood`、`command-gateway` |
| `skills/` | LLM 技能（10 个） | **模型自己决定**何时调用 | `skill.json` + `registerTool` + 提示词片段 | `calculator`、`weather-query` |

关键事实（决定你往哪个目录放东西）：
- **只有 `registerTool` 注册的工具会进模型的 tools 列表**——想接入 LLM 只有这一条路；只写 `providers` 的目录放 `skills/` 对模型完全隐形（加载器会打警告，见 `plugin-loader.js` 的 `lintKindPlacement`）。
- `plugins/` 与 `skills/` 的清单文件**功能完全等价**（同走 `src/skills/manifest.js` 的 `normalizeManifest`），区别只在「什么时候被执行」。
- 核心消费扩展一律按**能力名**（capability，如 `chat.ban-state`、`llm.request-params`），不 import 具体目录名——替换实现不需要改核心代码。
- **技能的工具与提示词段自 8fec2c8（jev 级联 PR1，2026-09-27）起参与工具门控**：`api.toolGate`（rules/jev/jev2）按 `skill.json` 的 `gateCategory` 裁技能工具与技能提示词段（同一份判定、同一时刻变化，见 §5 `api.toolGate` 行）；`plugins/` 与 `gateCategory: core` 技能恒常驻，不参与门控。

### 2.2 生命周期事件总线（`src/event-bus.js`）

核心行为的观察/审计/装饰通道，订阅者异常全部隔离（一个崩不影响别人和主流程）：

| 事件 | payload 要点 | 发射点 |
|---|---|---|
| `llm.request.before` | provider, model, messageCount, toolsCount | `src/llm.js` |
| `llm.request.after` | provider, model, ok, durationMs, usage?, error? | `src/llm.js` |
| `tool.call.before` | name, chatKey, argsRaw | `src/orchestrator.js`（executeTool 路径） |
| `tool.call.after` | name, chatKey, ok, durationMs | `src/orchestrator.js` |
| `message.sent` | chatKey, messageId, part/parts | `src/sender.js` |
| `module.loaded` / `module.unloaded` | id, name, version / id, reason | `src/module-loader.js` |
| `message.before-send`、`data.migrated` | （目录声明） | ⚠️ 声明于 `LIFE_CYCLE_EVENTS`，**当前无发射点**（见 §8） |

API：`on(name, fn, { weight, once })`（weight 小先执行，默认 100）、`emit`（不等待）、`emitSync`（等待全部）、`offByOwner(moduleId)`（卸载批量退订）。事件名必须小写点分（`validName` 校验）。

注意与 `util.js` 里 `createEventBus` 的区别：那条是 UI 刷新信号（SSE 推给前端），这条是核心生命周期。别混。

### 2.3 统一组件注册表（`src/module-registry.js`）

`modules/` 向核心注册组件的唯一入口（`createModuleApi(moduleId, context)` 返回的 api 面）：

| 组件 | 方法 | 分发方 |
|---|---|---|
| HTTP 路由 | `api.registerRoute({ method, pattern, handler })` | `app.js` `handleHttp` **先查表后走核心 if 链**（模块路由优先，pattern 支持 `:param` 段） |
| 事件订阅 | `api.on(event, fn, opts)` / `api.once` | event-bus（owner 登记为模块 id） |
| LLM 工具 | `api.registerTool(def)` | tool-registry → 模型 function 列表 |
| 插件存储 | `api.storage()` | `data/plugin-data/<id>/`（8MB 单文件上限、原子写） |
| 模块配置 | `api.config.get()/update(patch)` | 写进 `config.modules.<id>`，UI 设置页可见 |
| 路径/全局 | `api.paths`、`api.globalConfig()` | paths.js getters |

卸载统一回收：`disposeModuleComponents(moduleId)` 批量退路由/事件/工具（`module-loader.js` 热重载与停用时调）。

### 2.4 两个加载器

- `src/module-loader.js`：扫 `modules/`，`setup(api)` 注入上下文，源码**签名去抖**热重载（编辑器触碰不触发，500ms 合并）；`watchModules()` 开监听。
- `src/plugin-loader.js`：扫 `skills/` + `plugins/`（幂等 `loadPlugins`），单扩展加载失败**不拖垮启动**且会带 `loadError` 注册（UI 的 `/api/skills` 能看到失败原因）；`pruneMissing` 对齐磁盘（删目录即清幽灵工具）。热重载同样 500ms 去抖。
- `src/skill-bridge.js`：核心侧的桥——`initExtensions()`（启动扫描）、`getExtensionPromptSections()`（技能提示词片段）、`hookBeforeTool()` 等五钩子的调用包装。

### 2.5 启动顺序（`src/app.js` start 流程）

`migrateLegacyLayout()`（旧数据搬 data/，幂等）→ HTTP 服务起（找空位端口）→ `initExtensions()`（skills/plugins）→ `loadModules()`（modules）→ `watchModules()`（热重载）→ OneBot 连接。日志统一进 `data/logs/`。

## 3. 数据目录体系（`src/paths.js`）

**总则：用户产生的、需要备份的全部在 `data/` 单根；程序自带的只读资产（themes/skills/plugins 源码）留程序根。**

```
data/                        ← 数据根（dataRoot()）
├── config.json                运行配置（出厂模板为根目录 config.example.json）
├── instance.lock              实例锁（src/instance-lock.js）
├── bot-state.json / sessions/ 会话与唤醒状态
├── memory/ memory-v2/         来源化记忆
├── plugin-data/<id>/          插件/技能/模块隔离存储（api.storage()）
├── personas/                  人设文件层（5 内置播种；支持 meta 头 .md、纯文本 .md/.txt、.json 三种格式，放入即生效）
├── themes/                    用户导入主题（内置在程序根 themes/）
├── logs/                      全部日志（37qag-YYYY-MM-DD.log、launch.log）
├── history-cold/ …            旧消息冷归档等，getter 见 paths.js
data-2/                       ← 第二实例（QQ_AGENT_PROFILE=2 时整根错开）
```

- 搬根环境变量：`QQ_AGENT_PROFILE`（→ `data-N/`，端口也 +1）、`QAG_DATA_HOME`（测试重定向整根）、`QQ_AGENT_PORT`（指定端口）。
- 业务模块**不要自己拼路径**，一律 `import { xxxDir } from './paths.js'`。
- 旧布局（根目录日志、`command_data/`）由 `migrateLegacyLayout()` 首次启动自动搬，幂等可重跑。

## 4. 双端启动指南

依赖：**Node ≥ 20**（`scripts/start.mjs` 启动时断言），桌面端另需 `npm install`（含 Electron）。Linux 服务器只装生产依赖即可 headless 跑。

### 4.1 统一启动器（推荐，双端同一入口）

```bash
node scripts/start.mjs                 # 自动：有 Electron+显示环境→桌面，否则 headless
node scripts/start.mjs --headless      # 服务器模式：node src/server.js，浏览器开 http://localhost:3210
node scripts/start.mjs --desktop       # 桌面模式：electron .
node scripts/start.mjs --profile 2     # 第二实例：data-2/ + 端口 3211
node scripts/start.mjs --debug         # 前台运行、控制台可见（排错首选）
node scripts/start.mjs --status        # 查看实例锁状态
```

npm 脚本等价：`npm start` / `npm run start:headless` / `npm run start:desktop`。

### 4.2 传统入口（全部保留，是 start.mjs 的薄包装）

| 系统 | 文件 | 等价命令 |
|---|---|---|
| Windows | `启动-单号.bat`、`启动-双号.bat` | start.mjs（powershell 链不变） |
| Windows | `启动-单号-调试模式.bat` | `--debug` 且保留可见控制台 |
| Linux/macOS | `启动-单号.sh`、`启动-双号.sh` | bash 包装；双号= B 号 `QQ_AGENT_PROFILE=2` 后台 headless + A 号前台 |
| Linux/macOS | `启动-单号-调试模式.sh` | `node scripts/start.mjs --debug --headless` |

双号要点：B 实例数据整根在 `data-2/`，日志 `data-2/logs/launch.log`；实例锁防同 profile 重复起。

### 4.3 首次配置（必填才通）

控制台「设置」页或直接编辑 `data/config.json`：
① `api.baseUrl`（OpenAI 兼容端点）② `api.model` ③ `api.apiKey` ④ SnowLuma WebSocket/HTTP 地址与令牌 ⑤ 群/私聊白名单（`allow`/`deny`）。
预置模板：复制根目录 `config.example.json` → `data/config.json` 再填真实值。改完重启。
