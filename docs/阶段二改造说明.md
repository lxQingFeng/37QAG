# 37QAG 阶段二架构改造说明（v0.6.0）

> 改造依据：群内《AstrBot-vs-37QAG 对比评估报告》《RiyaBot-vs-37QAG 对比评估报告》的 P0/P1 精华清单（仅模式移植，零代码复制 —— RiyaBot 为 GPL-3.0，本项目 MIT）。
> 三大目标：① Windows/Linux 双端适配；② 除核心聊天链路外全模块化（统一注册表/事件总线/进程内注册）；③ 数据收归 data/ 单根便于备份。
> 结果：**79/79 测试全绿（原 54 项 + 新增 25 项回归），headless 冒烟通过，26 skills + 16 plugins 无一回归**。

---

## 二、三大目标落地明细

### ① Windows/Linux 双端适配

| 位置 | 旧（Windows 假设） | 新（双端） |
|---|---|---|
| 启动入口 | 仅 bat/ps1 | + `node scripts/start.mjs`（自动判定桌面/无头）+ 三个 `.sh`（755）+ npm scripts |
| SnowLuma 进程 | `snowluma/node.exe` + `cmd /c launcher.bat` | node 二进制候选链（平台名→另一名→PATH node）；launcher 候选 `.sh`/`.bat` |
| 本地 Jev | `runtime/llama/llama-server.exe` | 平台默认名 + 找不到时自动试另一平台名（cfg.exePath 仍可覆盖） |
| 打开目录/浏览器 | `explorer.exe` / `cmd start` | `util.openPath()/openInBrowser()`：win/darwin/linux 三分支 + **spawn ENOENT 安全吞掉**（无桌面服务器不再崩进程，回归测试覆盖） |
| 启动日志 | 根目录 `launch-log.txt` | `data/logs/launch-log.txt`（ps1/sh/start.mjs 三端一致；旧文件自动迁移） |
| Electron | TitleBarOverlay win32 检查 | 保留（平台条件判断本身是正确降级） |

### ② 全模块化（统一注册表 / 事件总线 / 进程内注册）

- **统一组件注册表**（`src/module-registry.js`）：模块拿 `api` 注入面对核心注册四类组件——`registerRoute`（HTTP 路由，支持 `:参数` 段）/ `on`（生命周期事件，owner 退订）/ `registerTool`（转 tool-registry）/ `storage`（data/plugin-data/<id> 沙盒）；`context` 注入核心句柄（sender/onebot/store…软引用）。卸载时 `disposeModuleComponents()` 按模块批量回收，零残余（测试覆盖）。
- **生命周期事件总线**（`src/event-bus.js`）：10 事件 + weight 排序 + once/off/offByOwner + 订阅者异常隔离 + fire-and-forget（热路径零等待）。已接入：`llm.js`（请求前后含 usage 摘要）、`orchestrator.js` executeToolGuarded（工具前后）、`sender.js`（message.sent）。
- **模块加载器**（`src/module-loader.js`）：module.json 清单（id/kind/entry/configKeys/enabled）→ setup(api) → dispose；fs.watch 热重载（500ms 去抖 + 源码签名比对）。
- **command-gateway 补丁转正（核心痛点根治）**：原 8 文件 18 处 `[[command-gateway:…]]` 标记块（改核心源码+重启生效）**全部转正为核心原生代码**（app.js 会话前拦截点/插件资产服务、plugin-loader 插件存储、manifest 指令声明协议、manager 状态字段、electron 快捷键、ui 8 处）。patch.mjs 新增 `isBuiltin()` 指纹检测：0.6.0+ 核心 18/18 块 builtin（不打补丁、不停用时误摘）；旧核心（≤0.5.0）行为完全不变。**插件装卸不再需要重启核心**。
- **app.js 减负**：98 条 HTTP 路由 if 链前置模块路由表查询；api-news/themes/crazy-thursday 三模块从硬编码 import+挂载改为 modules/ 装载（对应 6 条路由移交模块注册，核心 if 链删除）。

### ③ data/ 单根统一

- **路径集中**：所有运行时数据路径从 12 个模块的散拼 `path.join(DATA_DIR,…)` 收敛到 `src/paths.js` getter（`dataRoot/logsDir/messagesDir/memoryDir/sessionsDir/pluginDataDir/userThemesDir/…`）。
- **环境变量搬根**：`QQ_AGENT_DATA_DIR`（原有）+ 新别名 `QAG_DATA_HOME`；冒烟验证：临时目录重定向下 memory/sessions/logs/plugin-data 全部跟随。
- **插件数据隔离**：`data/command_data/<id>` → `data/plugin-data/<id>`（loader 注入 `api.storage`，越界路径拒绝；`migrateLegacyLayout()` 首启自动搬，幂等，测试覆盖）。
- **杂项收编**：根目录 launch-log.txt → data/logs/；用户主题 → data/themes/（内置 themes/ 只读，`migrateUserThemesOut()` 自动分离，同 id 用户层优先）。
- **保留根目录的例外**：`desktop-prefs.json`（双号互通的设计意图，非备份范畴）、`models/ runtime/ snowluma/`（程序资产非用户数据）。

## 三、兼容性说明（不破坏现有功能）

1. **旧插件零改动**：skills/plugins 双轨与 capability 体系原样；command-gateway 1.5.0 在 0.6.0 核心上自动走 builtin（无需打补丁），在旧核心上补丁引擎照常工作（双态测试）。
2. **旧数据零丢失**：command_data/launch-log.txt/用户主题三类旧布局自动迁移（幂等，可重跑）；失败不阻塞启动。
3. **测试**：原 54 项全部保留并通过；新增 25 项（paths 7 / event-bus 7 / module-registry 5 / cross-platform 6）。`npm run check` 纳入全部新文件。
4. **接口语义不变**：模块路由与原核心路由逐字段对齐（含 `?force=1`、500 语义、404 文案）。

## 四、给后续阶段的建议（未在本轮实施）

- 命令组件 `registerCommand` 已在注册表预留接口位（会话前拦截链消费），可将 plugins/ 的命令声明逐步迁到 manifest commands + 注册表（RiyaBot 模式）。
- `plugin-loader` 与 `module-loader` 在阶段三可进一步收敛为同一加载器（当前刻意保留双轨，避免一次性大迁移风险）。
- MCP 客户端桥、任务分级模型（TaskConfig，与本地 Jev 咬合）按 AstrBot/RiyaBot 报告 P1/P2 推进。
