================================================================
  一、这是什么
================================================================

  一个跑在你自己电脑上的 QQ 群 AI 机器人。

  · 它不是一个「问答接口」，而是一个有状态、会挑时候说话的群友：
    群里没人叫它时它会自己判断要不要接话；被叫到一定回；
    它会记事（谁是谁、谁最近在忙什么）、有心情和精力、
    会发表情包、会搜网、会转发 B 站视频。
  · 它跑在你本机。配置、聊天记录、记忆全在包目录下的 data/ 里，
    不会上传到任何地方。
  · 它通过一个「协议端」（包内自带的 snowluma/）连上 QQ。
    协议端需要你用手机 QQ 扫码登录 —— 这一步只能你自己做。

  包里已经带好的东西：

    · 程序本体 + 控制台界面（浏览器打开就是控制台）
    · 21 个扩展（12 个插件 + 9 个技能，见【五、5.6】）
    · 一个本地小模型（0.8B，见【六】）—— 用来做"要不要接话"这类小判断，
      省云端 token，断网也能判
    · 一键启动脚本、说明文件

  包里没有、需要你自己准备的东西：

    · 模型 API Key（大脑，必须自己填，见【二】第 3 步）
    · QQ 账号（协议端扫码登录，见【二】第 2 步）
    · 你自己的群号 / 好友 QQ 号（加进白名单它才理）


================================================================
  二、五分钟上手
================================================================

  第 0 步：放好目录
  ----------------------------------------------------------------
  把整个文件夹解压到任意位置（D:\QQ-Agent 这种短路径最好）。
  别放在需要管理员权限的目录（如 C:\Program Files），
  也别放在网盘自动同步的目录里 —— 聊天记录是每天在长的文件。

  第 1 步：双击「启动-单号.bat」
  ----------------------------------------------------------------
  · 你只有**一个** QQ 号 → 点「启动-单号.bat」。
    要同时跑**两个** QQ 号 → 点「启动-双号.bat」（它会起两个控制台，
    一个号一份数据：data\ 与 data-2\，端口自动错开，见【八】）。
  · 会弹出一个黑色窗口（那是它的日志窗口，别关）。
  · 杀毒软件可能拦一下，选「允许」。
  · 浏览器会自动打开控制台： http://127.0.0.1:3210/
    端口被占用时它会自动往后找一个空位，真实地址打印在窗口里。
  · 窗口不见了 = 机器人关了。想彻底退出：右键托盘图标 → 退出。

  第 2 步：连 QQ（这一步最花时间）
  ----------------------------------------------------------------
  1) 控制台顶部 →「QQ 连接」页签 → 点「启动 SnowLuma」。
  2) 等它起来（几秒到几十秒），页面上会出现一个 WebUI 地址，点开。
  3) 第一次打开它的网页要登录：用户名 admin，
     密码是它启动时**打印在日志里**的一串随机码 ——
     在「QQ 连接」页下方"运行日志"里找这一行：
         initial credentials: user=admin password=xxxxxxxx
     进去后会先要求同意它的用户协议与隐私说明，同意完请**立刻改密码**。
  4) 在 SnowLuma 网页里用手机 QQ 扫码登录机器人要用的那个号。
  5) 回控制台看顶栏最左边的圆点：
        绿点 = OneBot 已连接，可以用了
        红点 = 还没连上（看「QQ 连接」页下方的运行日志）
  6) 建议顺手把「桥上账号白名单」填上机器人的 QQ 号：
     SnowLuma 的"自动注入"会发现一个 QQ 进程就挂一个，
     填了白名单它就只允许这个号上桥，发现别的号会报警（可自动卸载）。

  第 3 步：填模型 API（大脑）
  ----------------------------------------------------------------
  控制台 →「设置」→ 左侧「模型 API」：

  · 填 Base URL：OpenAI 兼容地址。例如
        百炼（通义）  https://dashscope.aliyuncs.com/compatible-mode/v1
        DeepSeek      https://api.deepseek.com/v1
        智谱          https://open.bigmodel.cn/api/paas/v4
        OpenRouter    https://openrouter.ai/api/v1
  · 填 API Key（去对应平台官网申请，一般有免费额度）。
  · 点「获取列表」拉模型，或手动填模型 id（如 qwen3.5-flash）。
  · 点「测试连通性」，显示「首字 X / 总计 Y」就通了。
  · 顺手点一下「扫描图片能力」：它会挨个给模型发一张纯色小图问颜色，
    判断这个模型到底能不能看图 —— 结果决定"看图工具"给不给它用。

  第 4 步：告诉它该理谁（白名单）
  ----------------------------------------------------------------
  控制台 →「设置」→「聊天白名单」：把要它参与的群 / 好友加进去。
  · 有「选择群」「选择好友」按钮，直接从 QQ 账号拉列表勾选，不用手抄群号。
  · 白名单为空 + 「白名单留空时允许所有会话」没勾 = 它谁都不理
    （这是故意的，防止刚装好就被拉进莫名其妙的群）。
  · 想临时让它闭嘴：顶栏「暂停」按钮；恢复也是同一个按钮
    （横幅里还有「恢复并全部标为已读」，暂停期间积压的消息不再处理）。

  第 5 步：确认它活着
  ----------------------------------------------------------------
  · 在目标群里发一条 @它 的消息。
  · 控制台 →「会话」页签左侧会出现这个群，右侧是这一轮的完整过程：
    它看到了什么、想了什么、调用了哪些工具、最后发了什么。
  · 没反应？翻【十、常见问题】第 1 条。


================================================================
  三、界面导览
================================================================

  3.1 顶栏（任何时候都在）
  ----------------------------------------------------------------
  [OneBot 圆点]  绿=已连上（悬停能看到登录的昵称），红=没连上，
                 灰黄=曾经连上过但现在断了。
  [模型]         当前聊天模型。
  [今日]         今日用量 / 缓存命中：跑了多少次、多少 token、
                 缓存命中率、花了多少钱、缓存保温发了几棒。
  [小模型]       本地 0.8B 的状态，五种：缺文件 / 未启用 / 就绪 /
                 启动中 / 未启动。
                 **点一下**：没启用就启用并拉起；已就绪就跳到设置页。
  [搜]           今天联网搜索了几次。
  [状态]         本体状态（跨群）：精力 · 心情 · 社交电池。
                 页面最右侧那条也是它，点一下进「情绪」页。
  [主题按钮]     暗色 → 亮色 → 跟随系统 → ？，四档循环。
  [更多 ···]     三个按钮：
                 · 热重载：重读磁盘配置并重建工具（改完人设/白名单/
                   扩展后点它，不用重启程序）
                 · 金句上传：勾选机器人的精彩发言，收录到作者的金句墙
                   （**会把选中的消息上传到作者的服务器**，见【十一】）
                 · 意见收集：给作者提意见（同样会联网上传，可附图）
  [暂停]         一键让它不说话。程序还在跑、消息照收，只是不处理。
  [窗口按钮]     最小化 / 最大化 / 关闭。**关闭 = 收进托盘**，
                 不是退出；要真退出用托盘右键菜单。

  顶栏的每个胶囊、页签顺序都能在「设置 → 桌面端 → 顶部工具栏自定义」
  里隐藏或拖动排序（藏了「更多」就没热重载入口，慎重）。

  3.2 页签（从左到右）
  ----------------------------------------------------------------
  会话    每个群/好友一轮对话的运行全过程：触发消息、注入的记忆、
          工具调用、最终发出的消息。排查"它为什么不回 / 为什么这么回"
          就看这里。
  存档    原始消息记录（按会话分），可以翻很久以前的。
          也是「金句上传」勾选消息的地方。
  记忆    按人（跨群）看它记住的东西：印象、近况、好感度、态度。
          可以手动改、删、加（见【五、5.1】）。
  知识库  梗库（群内黑话、结论）、外部百科源、图库。
  情绪    心情 / 唤醒 / 急压 / 慢压 + 四维精力（身体·认知·情绪·意志），
          还有「亢奋模式」。
  世界    世界设定、事件池、近况账本、节假日日历、精力目标
          （由 life-system 插件提供，默认关，见【五、5.4】）。
  工具    两块：扩展（插件 + 技能，机器人的能力，开关即生效）
          和 模型工具（模型能调用的动作，勾选后才交给它）。
  用量    花了多少钱、调了多少次、搜了多少次、输入了多少 token，
          可按今天 / 7 天 / 30 天 / 全部切换，点行还能下钻。
  QQ 连接 SnowLuma 的启动 / 停止 / 日志，以及桥上账号白名单。
  设置    10 个分区，见【四】。
  免费API 每天凌晨自动抓的「免费额度 / 限时免费」情报。


================================================================
  四、设置逐项说明
================================================================

  先记三条规矩：

    1. 改动**即时自动保存**（停止输入约 0.6 秒后写入），不用点保存。
    2. 但「人设 / 白名单 / 扩展」改完，要再点左下角的
       「热重载配置」才真正生效。
    3. 左侧分三组：连接（模型 API / 搜索服务 / 浏览锁定 / OneBot）、
       行为（聊天白名单 / 聊天与节奏 / 记忆 / 本地 Jev / 人设）、
       界面（桌面端）。

  ----------------------------------------------------------------
  4.1 模型 API（连接组）
  ----------------------------------------------------------------
  管"大脑"：用哪个模型、怎么调它、怎么省钱。

  【模型】
  · 当前模型     点一下弹出模型选择器（按提供商分组，可搜索）。
  · 测试连通性   发一条最小请求，显示「首字 X / 总计 Y」。
  · Base URL     只读，跟着当前提供商走；旁边「获取列表」拉模型清单。
  · API Key      密码框。**留空保存 = 保持原来的 Key 不变**（不会清掉）。
  · 扫描图片能力 挨个给模型发纯色图问颜色，判断"能不能看图"，
                 结果写进配置、用来门控看图类工具。换模型后建议重扫。
  · 手动添加提供商  填 Base URL + Key，可「获取列表」勾选模型加入；
                 支持多个提供商（`providers[]`），随时切换。

  【采样与思考】
  · 温度                 0–2，越高越发散。默认 0.8。
  · 单次最大工具轮数     默认 12（1–40）。一次运行里模型最多调几轮工具。
  · 自动收尾             默认开。一轮里话已发完、又没有待办（找图/搜索）
                         时直接结束，不再为"补一句 finish"多跑一轮。
    └ 单条回复也收尾      默认不勾（只在已发出 ≥2 条时收尾）。勾上更省，
                         但可能少补一句。
  · 图片输入             默认开。关掉 = 移除看图工具，模型只看到 [图片] 占位。
                         模型被扫出"不支持图片"时这一项会自己禁用。
  · 关闭模型思考模式     默认关。会自动适配百炼 / 方舟 / 智谱 / Kimi /
                         DeepSeek / 硅基流动等；不认参数会自动回退。
  · 思考长度上限         默认 64（0=不限）。数值越大越慢也越稳。
                         保存后热重载生效。

  【上下文缓存】—— 最省钱的一项
  · 上下文缓存模式       四档：
        自适应 + 保温（推荐）  保温开着就始终打显式标记，并每 4 分钟
                              发一次极小请求把 5 分钟 TTL 续住
        隐式缓存              只靠平台自动缓存
        显式缓存（只打标记）   不保温
        关闭缓存布局          默认就是这一档
  · 缓存保温             默认开。每 4 分钟一次 1-token 的极小请求续 TTL，
                         群里安静 10 分钟后自动停。一次约 ¥0.0001，
                         换的是下一次请求命中缓存（命中只按 10% 计价）。

  【成本护栏】
  · 启用成本护栏         默认开。触顶后只砍"可选注入块"，
                         核心人设与本次消息照发。
  · 今日 prompt 上限     默认 800000 token（0=不限）。
  · 单群 prompt 上限     默认 200000 token（0=不限）。

  【架构增强（本地短注入）】
  · 跨轮工作记忆         默认**关**。让它在连续几轮里记得"上一轮干到哪了"。
    └ 有效期 / 静默淡忘间隔 / 最长字数   默认 90 分钟 / 30 分钟 / 160 字。
  · 语义卡片             默认**关**。把零散印象收成短卡。
    └ 每轮注入语义卡数     默认 2 张（0–8）。
  · 短时跨群感知         默认**关**。知道隔壁群刚在聊什么（只给话题词）。
    └ 时间窗 / 最多看几个群 / 最长字数   默认 10 分钟 / 2 个 / 120 字。
  · 待办状态机           默认**开**。模型自己定的待办，到点不再注入。
  这几项都是**成本开关**：开得越多它越聪明、也越贵。

  【成本核算】
  · 用内置官方价格表估算  默认开。按模型 id 自动匹配内置价格表
                          （走中转站请关掉，价格会不准）。
  · 远程价格表 URL        填了之后启动时与每 24 小时自动拉一次。
  · 输入 / 输出 / 缓存命中 单价（元/百万 token）。
                         开着官方表时这三个框只读；要自定义先关掉它。

  ----------------------------------------------------------------
  4.2 搜索服务（连接组）
  ----------------------------------------------------------------
  管它怎么上网查东西。

  · 联网搜索：启用 web_search / web_fetch 工具
        默认开。关掉 = 联网搜索与抓网页全停（省钱最狠的一刀）。
  · 抓网页正文上限        默认 8000 字符。中文 1 字 ≈ 1 token，
        抓 2 万字就是一次 ¥0.01+，比一次正常运行还贵 —— 所以压得很低。
  · 搜索提供方            默认 native（用当前聊天模型自带的联网，
        失败自动退回 Bing）。可选：
              native   模型原生联网（enable_search，推荐）
              bing     抓 Bing 结果页（不用 Key）
              deepseek / zhipu / bocha / baidu / metaso   各自要 Key
              custom:<id>  你自己的搜索服务
  · 搜索地址（Bing 分支） 默认 https://cn.bing.com/search
  · 各家 API Key          DeepSeek / 智谱（按次计费：基础 ¥0.01、
        高级 ¥0.03、搜狗/夸克 ¥0.05）/ 博查 / 百度千帆 / 秘塔（可选，
        留空会试免费额度）。留空时回退同名环境变量。
  · B 站 Cookie          点「一键登录 B 站」弹窗登录后自动写入
        （需要桌面壳）；官方 AI 总结 / AI 字幕要用它，热评弹幕不需要。
  · 自定义搜索服务        名称 / 类型（JSON 接口 或 抓网页解析）/
        接口地址 / API Key（可选）/ 模型名（可选）。
        填完可「测试这个搜索服务」，返回「✓ 可用（N 条结果，Xms）」。
        （顺手说一句：外部百科源 MediaWiki 不在这个分区，
          它在顶部「知识库」页签里管。）

  ----------------------------------------------------------------
  4.3 浏览锁定（连接组）
  ----------------------------------------------------------------
  把机器人的"上网范围"锁死在指定站点里，默认关。

  · 启用浏览锁定          打开后：抓网页（web_fetch）、下网图（send_image）
        只能访问这些域名，站外搜索结果会被滤掉。
        表情包和群聊图片（QQ 自己的图源）不受影响。
  · 允许的站点            每行一个，可不带 http://。
        例：zh.wikipedia.org / bilibili.com
  · 粘贴一个网址，自动提取站点    懒得写就粘一条网址，点「加入」。
  · 连带子域名一起放行    默认开（bilibili.com 允许 www./m./api.）。
  · 站内搜索地址          可填 {query} 占位符。填了之后机器人直接抓这个
        地址在锁定站点内搜，少一轮全网检索；留空则自动加 site:你的站点。
        例：https://zh.wikipedia.org/w/index.php?search={query}
        （页面有实时预览，会告诉你"搜「猫」时会抓哪个地址"。）
  · 允许访问内网 / 本机地址  默认关。自建 wiki、局域网图床时才开，
        开了等于允许机器人访问你局域网里的东西，风险自负。
  · 当前状态（只读）      三种：已锁定在 X / 已开启但站点列表是空的
        （空列表等于不锁定）/ 未启用（可访问任意公网地址，内网始终拒绝）。

  ----------------------------------------------------------------
  4.4 OneBot（连接组）
  ----------------------------------------------------------------
  · SnowLuma 程序目录     默认留空 = 用包内的 snowluma/。
  · 启动时自动拉起 SnowLuma   默认关（建议也保持关着，
        手动去「QQ 连接」页启动，或者用 snowluma\launcher.bat 独立启动）。
  · WebSocket 地址        默认 ws://127.0.0.1:3001（收消息）。
  · HTTP 地址             默认 http://127.0.0.1:3000（发消息）。
  · WebSocket 令牌 / HTTP 令牌   一般不用填（SnowLuma 里两套是分开的）。
  · 改完 OneBot 地址要重启应用才生效；模型/人设/白名单是即时生效。

  用包内 SnowLuma 的话这里一般不用动；换成别的协议端
  （NapCat / LLBot 等，只要提供 OneBot v11 正向 WebSocket）就改这里。

  ----------------------------------------------------------------
  4.5 聊天白名单（行为组）
  ----------------------------------------------------------------
  · 从 QQ 账号直接勾选    两颗按钮：「选择群」「选择好友」。
        点开是从 QQ 拉列表勾选，勾完自动填到下面两个框。
  · 允许的群号 / 允许的 QQ  逗号分隔。
  · 白名单留空时允许所有会话   默认不勾。勾上 = 谁找它都理（不推荐）。
  · 疯狂星期四白名单      每周四 07:00 / 13:00 / 19:00 向这些群直发
        玩梗文案（不走人设、不调用模型）。**留空 = 不向任何群发送**
        （它不会跟着上面的"允许的群号"走，要发就得单独写群号）。

  一个小坑：这个页面点保存时会把配置文件里的"黑名单"（deny）清空。
  要长期用黑名单的话，手工改 config.json 里的 deny，之后别在这个页面
  点保存（或者改完再补回去）。

  ----------------------------------------------------------------
  4.6 聊天与节奏（行为组）
  ----------------------------------------------------------------
  这一段决定"它什么时候开口、一次说几句"。默认值是按真实群聊调过的，
  建议先别动，遇到具体问题再回来改。

  【运行节奏】
  · 亢奋最低发言条数    默认 5（仅亢奋模式生效，0=不限）。
  · 防抖聚批窗口        默认 2000 毫秒。收到消息先等等，把连发聚成一批。
  · 连发静默等待        默认 15000 毫秒。对方在连发时，"最后一条之后再等多久"。
  · 连发最长等待        默认 30000 毫秒。一串话最多等到这时候就开跑。
        被 @ 或命中关键词、以及隔了一阵子的第一条消息不受影响，仍然秒回。
        **两个都填 0 = 关闭连发合并**。
  · 批次间隔            默认 1200 毫秒。上一轮结束发现还有未读，隔多久开下一轮。
  · 同时处理会话数      默认 2（1–8）。
  · 连发窗口按「这个人爱不爱连发」自适应   默认开。说完就走的人少等
        （约 5 秒），爱一条条补的人多等（给满"连发静默等待"）。
  · 连发合并交给本地 Jev 判（说完了就秒回）  默认关。
        打开后：连发时先问本地小模型"他这句说完了没"，说完了且够自信
        就把等待缩回防抖窗口；**只做缩短，不做延长**。
    └ 判定门槛（概率 / 前二名间隔）  默认 0.8 / 1.0，越大越保守。

  【发送保护】
  · 相邻消息最小间隔    默认 1000 毫秒（防刷屏）。
  · 相邻消息最大间隔    默认 3000 毫秒（超过则切段）。
  · 每分钟 / 每小时最多发送   默认 80 / 500 条（硬限流）。
  · 按字数附加间隔      默认 20 毫秒/字（长文稍慢）。
  · 硬切分长度          默认 4000 字（0=不切）。
  · 另外配置文件里还有几个没上界面的：
        单轮最多发几条文字（send.maxPerRun，默认 4）、
        超长按标点自动拆分（send.splitLongAt，默认 0=不拆）、
        整段英文拦截（send.blockPureEnglish，默认开）。

  【表情包与网图】
  · 启用表情包          默认开（收藏表情同步 + 发送工具）。
  · 发表情积极程度      0 不鼓励 / 1 偶尔 / 2 较积极 / 3 很积极。
        这是提示词层面的引导，不是强制每次都发。
  · 提示词列几张表情    默认 12 张（2–30）。每张约 45 token，12 张 ≈ 540。
  · 列表轮换周期        默认 60 分钟。列表一半固定常用、一半按周期轮换
        （优先挑没用过的），避免"只按使用次数"越用越偏。
  · 给没备注的表情补描述  按钮。没备注的表情模型不知道何时该发，
        补一句描述后更容易出场（约 ¥0.001/张）。
        它也是"分不清哪个是哪个"的解药：列表里没描述的表情，模型只能瞎猜；
        补完之后每张都有名字，它才会挑得准、发完也知道自己发的是哪张。
  · 允许机器人发网图    默认开。下面几项一起管着它：
        发送前必须先「看一眼」（视觉模型确认合适再发，默认开）、
        锁定站点里的图例外（省视觉 token，默认开）、
        一次最多发几张（默认 2）、单张大小上限（默认 5MB）。
        只接受 http(s) 图片直链，内网地址一律拒绝。

  【响应档位】—— 决定"何时开口"
  · 一条滑条分四段（群聊、私聊各一条）：
        1 档  仅被 @ 时回应，其余静默（最省）
        2 档  被 @ 或命中关键词时回应
        3 档  被 @ / 关键词必回应；普通消息按"接话意愿 X%"回应
              （越小越挑，同时决定每小时最多主动插几次）
        4 档  任何消息都回应（默认）
  · 私聊单独设置        默认不勾 = 私聊沿用群聊参数。
        勾上后私聊有一套自己的档位与条数（私聊一般不会 @ 它，
        共用群聊的"随机概率"会导致私聊消息被概率性漏掉）。
  · 下面的数字是"开口时带入的已读条数"：
        艾特 20 条 / 关键词 15 条 / 随机 8 条 / 其余 80 条。
  · 更多设置：关键词表（每行一个，不区分大小写）、
        注入近 24h 本地摘要（默认关，可设小时/最长字数/短句数）。
  · 单个会话单独设置    展开某个群/好友并勾选「这个会话单独设置」，
        可以只给这一个会话调档位。优先级：单独设置 > 私聊 > 群聊。

  ----------------------------------------------------------------
  4.7 记忆（行为组）
  ----------------------------------------------------------------
  这一页是「记忆整理」：什么时候自动收拾记忆库。

  · 启用记忆自动整理    默认开。条数超阈值且距上次整理超过最小间隔，
        才在运行结束后自动整理（合并重复印象、删过期的）。
  · 使用与聊天机器人相同的模型   默认开。
        取消勾选才展开「记忆整理模型」，可以指定一个更便宜的专用模型。
  · 整理最小间隔        默认 168 小时（7 天）。
        一天一次容易删太多，所以默认一周。
  · 每人超过多少条才自动整理   默认 12 条。
        注意：这是**触发整理的阈值，不是记忆上限** —— 印象本身不设上限。

  （"上下文读多少条"不在这页，在【4.6 响应档位】里。）

  ----------------------------------------------------------------
  4.8 本地 Jev（行为组）
  ----------------------------------------------------------------
  包内那个 0.8B 小模型（原理见【六】）。这一页能改的：

  【开关与文件】
  · 启用本地 Jev        默认开。关掉 = 所有判定回到词表 / 云端，
        不省也不额外花时间。
  · 打开软件时自动拉起   默认开。关掉 = 懒启动（第一次真要用才起进程，
        省内存，第一问多等几百毫秒）。
  · 本地模型文件        下拉选 models/ 下的 .gguf（默认 0.8B 那个）。
  · 请求里的模型名 / 端口 / 上下文长度 / 并发请求数
        默认 qwen3.5-0.8b / 18080 / 4096 / 2。
  · 待判文本截断        默认 160 字。越短越快（本地模型最贵的是读题）。
  · 弃权阈值（概率 / 前二名间隔）   默认 0.6 / 1.0。
        两个都过才采信，不过就弃权走原逻辑。
        "概率"取「标签分布占比」与「模型吐这个标签有多果断」的较小值；
        单个角色可以自带阈值（情绪判定用的是 0.45）。
  · 每条消息的门控时间预算   默认 1500 毫秒。到点就用已判出的结果，
        剩下的弃权。
  · 用 grammar 硬约束输出   默认开（避免它答一句废话导致解析失败）。

  【插话判定（随机档"该不该插一句"）】
  · 判定方式            Jev 读内容判定（默认）/ 纯概率骰子（不看内容）。
  · 插嘴冷却            默认 90 秒（按群计）。
  · 每小时上限          默认 8 次（全局，0=不限）。
  · 插嘴专用间隔阈值    默认 1.0（只对 Jev 模式生效，比弃权阈值更严）。
  · 按群活跃度自适应    默认开：越热闹越克制，越冷清越愿意接。
        ⚠️ 2026-09-22 改了联动关系（用户反馈「90 的回应率都很低，响应概率和
        自适应冲突了」）。现在的规矩一句话：
          **响应概率（插话意愿）= 你要的下限；自适应只能在它附近的窄带里微调。**
          概率门槛 ±0.08、间隔门槛 ±0.40、每小时上限 0.7~1.3 倍、冷却 0.7~1.35 倍，
          超出带子的一律夹回边界。于是"意愿 90%"在任何群里都至少有 90% 该有的机会
          （实测：意愿 90% + 中等活跃 → 约 8 次/时、间隔 139 秒；
          而旧版取严的算法只给 5 次/时、240 秒，这才是"设了 90% 也不主动"的原因）。
          热度还做了 h^1.6 折算：中等活跃的群不再被当成"刷屏"，只有真刷屏才收紧。
          低意愿仍然很严（意愿 5% → 每次间隔门槛 4.2、每小时最多 1 次）。

  【云端升级（可选，默认关）】
  本地弃权时，把这一题升级给一个便宜的云端小模型再判一次。
  要填：端点地址、API Key、模型名、本地低于多少才升级（默认 0.6）、
  云端自己的弃权阈值（默认 0.6）、单价（只用于统计）、每分钟最多问几次。
  · 想**完全不跑本地模型**、只用云端判定：把上面「启用本地 Jev」取消勾选，
    这里填好地址与模型就行 —— 本地关掉后所有判定改走云端通道。
    （代价：每次判定都变成一次网络请求，延迟与费用都会上去，
      建议把「接管哪些判定」收窄到真正需要的几个。）
  · 「端点不给概率时按这个置信采信」：有些官方端点/中转不返回 logprobs，
    以前这种情况一律弃权、等于云端白配；填 0.7 之类的值就会按这个固定置信采信。
    默认 0 = 保持旧行为（拿不到概率就弃权）。
  · 设置页会显示云端**最近一次的错误原因**（401/404/超时都会写出来）；
    以前只显示"失败 N 次"，看不出为什么一直不生效。

  【接管哪些判定】
  逐角色勾选（文本判定、插话闸、记忆召回、情绪、表情、梗、语义卡准入、
  外部知识……一共十来个）。每行都会显示这个角色判过多少次、
  平均多少毫秒、弃权/失败多少次。**没勾的角色走原来的词表/云端逻辑。**

  【工具】
  · 重启本地模型        换模型文件或改端口后点这个才生效。
  · 停掉它              下次判定会自动再拉起。
  · 清空统计            重置上面的次数/耗时统计。
  · 试判                选一个判定类型 → 输一句话 → 点「判一下」，
        直接看它会给出什么结论、概率多少、耗时多少。
        调阈值之前强烈建议先用它试几把。

  页面顶部还会显示：本地模型状态（已就绪 / 已启用未起来 / 已关闭）、
  云端通道状态、以及最后一次报错。

  4.9 人设（行为组）
  ----------------------------------------------------------------
  · 选择人设            点开人设库挑一个（内置「小鲸鱼」模板）；
        也可以「＋ 添加人设」写自己的，「删除当前自定义人设」删掉。
        ⚠️ 2026-09-22 起：**点中哪张卡就立刻生效并保存**（不用再点「保存人设修改」，
        那一步只用于你手改了正文之后）。选完卡片会在下面回一句
        「已应用并保存：xxx ✓」；如果你手改过正文，再点一次保存按钮。
  · 机器人名字          默认「小鲸鱼」。显示用。
  · 群内展示名          可选，留空 = 用 QQ 昵称。
  · 参与度              安静型 / 普通群友 / 活跃型。影响它主动说话的门槛。
  · 角色设定            写进 system 的身份：说话风格、雷点、
        群聊铁律（去 AI 味那几条）、示例对话。
  · 管理员附加规则      可选，追加到系统提示（比如"某人骂你别往心里去"）。
        选人设卡时，只有那张卡自己带了附加规则才会替换它，否则保留你写好的。
  · 极简系统提示        小模型 / 短上下文时建议开：只留最短的 system 规则。
  · 系统提示风格        完整（原版分节）/ 精简 lean。只改 system 规则块，
        角色卡不受影响。保存后热重载。

  · 清洗消息记录        就在人设这一块下面（2026-09-22 新增）。
        换完人设之后，它还会被自己**旧人设时期的聊天记录**拽着走
        （上下文里全是老自称、老语气），这时候清一遍最干脆：
          范围：当前选中的会话 / 全部会话（所有群 + 私聊）
          勾选：消息记录（data/messages/ 含冷分片）、会话存档（data/sessions/）
        点了会二次确认，**真的删磁盘文件、不可撤销**；正在运行的会话会跳过。
        好感 / 印象 / 语义卡不在这里清 —— 那些在「记忆」页逐条删。
        手动去删 data/messages、data/sessions 里的文件也可以：现在删完列表会自己
        把"文件已经不在"的条目丢掉，不会再出现"删了还显示"的幽灵记录
        （带 BOM 的存档文件也能正常读了 —— 记事本改过的文件以前会被静默跳过）。

  小提示：角色卡里有一段「## 自我印象」是它自己攒的（"我是谁、
  在群里是什么位置"），换卡时代码会保住这一段，不会被顶掉。

  · 导航页签 / 顶部工具栏自定义   拖动排序、取消勾选 = 隐藏；

  · 显示账号标签（本机多实例一键切换）   默认**关**（2026-09-22 改成默认关）。
        开着时顶栏会扫本机 3210-3239 端口，把"还有哪些 QQ-Agent 实例活着"列成一排按钮，
        点一下跳过去。**为什么默认关**：它只看端口上有没有人应答 —— 别的盘上那份副本、
        甚至"文件夹已经删了但进程还没退"的残留实例都会被列成按钮（表现为"删了还在"），
        点过去还可能因为对面界面不全而**一片黑**。两个号请用「启动-双号.bat」
        （同一个窗口里切换，不需要这个）。真要开就勾上这一条，界面里会写明风险。
  · 群成员备注          QQ 号 + 备注名。模型在记忆与回复里会优先用备注称呼。

  五、功能手册
================================================================

  5.1 记忆系统（它记得住人，但不会记得太死）
  ----------------------------------------------------------------
  分四层，从"人"到"事"：

  (1) 人物印象（长期）  「谁喜欢猫」「谁在读大二」「谁讨厌被开玩笑」
      · 模型自己判断值不值得记
      · 每人默认每轮只注入最新 2 条 —— 所以它会"选择性想起来"
      · 在「记忆」页可以手动加、改、删；跨群共享
        （这个人在别的群说的话它也记得）

  (2) 表层近况（短期，会**半衰**）  「他刚说在加班」「她困了」
      · 权重按 0.5 的（时间 / 半衰期）次方衰减，
        两个半衰期之后自动不再注入，然后被清掉
      · 所以"我好累"这种不会永久挂在这个人身上
      · 在「记忆」页能看到当前浓度，也能手动点掉

  (3) 语义卡片（中期）  把零散印象收成短卡（计划 / 事实）。
      入库前会问一次小模型"值不值得长期记"，垃圾卡会被清理。
      （默认关，见【4.1 架构增强】；打开后每轮注入几张可调。）

  (4) 跨轮 / 跨群 / 待办
      · 跨轮工作记忆：连着几轮说话时，它知道上一轮干到哪了（默认关）
      · 跨群感知：隔壁群在聊什么话题，只给话题词不给原文（默认关）
      · 待办：它自己定的"等会儿要问的事"，到点不再注入（默认开）

  · 好感度（0~100）：被夸会涨、被怼会掉（有防误伤规则）。
    高好感会顺着说、帮腔；低好感少理。可以在记忆页手改。
  · 态度：给某个人单独写一句语气要求（"对他要顺着说"），
    有态度时优先于好感度。
  · 搜旧聊天 / 聊天归档：它想找"上次说的那家店"时会去翻自己的历史。

  5.2 情绪与精力（它有自己的状态）
  ----------------------------------------------------------------
  · 心情（0~100，50 中性）、唤醒、急压（刚被刺激）、慢压（一直没歇）
  · 四维精力：身体 / 认知 / 情绪 / 意志 —— 熬夜、连聊都会消耗，
    被夸、休息会回一点。精力低时它更短、更懒得接话。
  · 情绪页能看当前值和曲线，也能手动调（改完接下来的语气会变）。
  · 亢奋模式：手动开关，不会自动触发。打开后模型 / 协议 / 人设卡一起换，
    情绪拉满、约束放松 —— 整活用，别长期开。

  5.3 表情包
  ----------------------------------------------------------------
  · 它会收藏群里的表情（默认每小时最多 10 张）
  · 提示词里默认列 12 张（一半常用、一半轮换，约 540 token）；
    库越大越该把轮换周期调短，否则新表情永远排不上
  · 它可以给表情写备注（什么场合用），搜表情也靠这些备注
  · 嫌费 token：把"提示词列几张"调小，或直接关掉表情功能

  5.4 世界与事件（life-system 插件，默认关）
  ----------------------------------------------------------------
  · 世界设定：只写世界（城市、天气、行规），**不要写人设**
  · 近况账本：默认用正则从它自己的话里抓"我吃了 / 我困了 / 在忙"
  · 事件池：打开后按节奏（每天最多几条、间隔多久、多久不重复）
    从池子里抽事件，让它有"自己的生活"
  · 节假日日历：只在中国法定节假日 / 调休前后补一行，普通日子不注入
  · 精力目标：可以按日历 / 账本轻调它的精力（周末更精神之类）

  5.5 知识库
  ----------------------------------------------------------------
  · 梗库：群里反复出现的黑话、结论、梗（模型存梗前会问一次小模型
    "以后还能复用吗"）。每条都带触发词，聊天时可能"顺手接一个梗"。
  · 外部百科源：MediaWiki 源，格式「id | 显示名 | https://根地址」。
    模型用 external_lookup 查它（问设定、角色出处这类）。
    注意这里是**知识库页签**里管，不在「设置 → 搜索服务」里。
  · 图库：和表情包分开的"正经图库"，可以搜图库再发。

  5.6 工具与扩展
  ----------------------------------------------------------------
  「工具」页分三块，从上到下：**插件一行 → 技能一行 → 模型工具白名单**。

  · 插件 plugins/<id>/：规则写死的确定性逻辑（比如"被禁言就不发消息"），
            给的是一致性保障，必然执行，不经过模型判断。
            插件每行 5 个，多了在标题右边出「‹ 1/3 ›」翻页（不再往下堆成长列表）。
  · 技能 skills/<id>/：注册工具交给模型，模型自己决定何时调用。
            技能数量少，一行铺开，不翻页。
    两行里的每个小卡片：左边勾选框 = 开关（点完即生效），
    右边「设置 / 详情」按钮点开就是该扩展**按它自己的配置清单自动生成的表单**
    （开关 / 数字 / 下拉 / 多行文本 / 密码框 / 字段联动显隐 / 只读项），
    改完保存即可，不需要改界面代码。
    标题右边的「打开 plugins / skills」按钮直接打开对应文件夹。

  · 模型工具白名单 —— 勾选后才交给模型。
    不勾 = 模型看不到这个工具（既省 token 又防乱用）。
    例：不想让它发网图，就把 send_image / search_images 取消勾选。

  包内 21 个扩展里，默认开的 8 个：
      禁言状态、图片格式兼容、发言人身份、思考模式适配、
      视频抽帧（需要本机有 ffmpeg，没有会自己标"不可用"）、
      计算器、文本工具、天气查询
  其余默认关（与核心功能重复，或需要外部依赖 / 密钥），
  要用自己去「工具」页打开。

  5.7 免费 API 情报
  ----------------------------------------------------------------
  每天凌晨 4 点抓一次"免费额度 / 限时免费 / 即将开放"类信息，
  压成人话 + 附链接，显示在「免费API」页签。省钱用。
  不想要这个页签：设置 → 桌面端 → 隐藏顶部「免费API」页签。


================================================================
  六、本地小模型（Jev）
================================================================

  6.1 它是干什么的
  ----------------------------------------------------------------
  包里带了一个 0.8B 的小模型（Qwen3.5-0.8B-Q6_K.gguf，约 600MB）
  和一个 CPU 版推理运行时（runtime/llama/）。

  它**不当聊天主脑**，只做"选择题"—— 每次问一个原子问题，
  它回答一个标签（YES/NO、SELF/OTHER、梗/怼/无……），
  用标签分布的概率决定采不采信。它负责的判定包括：

    · 这轮值不值得插一句（插话闸）
    · 对方这句说完没有（连发合并的等待窗口）
    · 这句话是什么情绪 / 意图（夸、怼、玩闹、求助……）
    · 要不要发表情、挑哪张
    · 群友发的图跟当前话题有关吗（无关就不附图）
    · 这条印象 / 语义卡值不值得长期记
    · 这条梗现在用得上吗
    · 这句话是在说它自己吗（吃 / 睡 / 累 / 忙）
    …… 一共十几个角色，每个都能单独开关（见【4.8】）。

  好处：这些判定如果都问云端模型，每天是几百次小额调用；
  本地做掉就是 **0 成本 + 不占网络**，断网也照常判。

  6.2 怎么用
  ----------------------------------------------------------------
  · 默认开机自动拉起（占几百 MB 内存，端口 18080）。
  · 顶栏「小模型」胶囊：显示状态，点一下 = 启用并立刻拉起。
  · 不想跑它：设置 → 本地 Jev → 关总开关（功能自动退回词表 / 云端）。
  · CPU 上一次判定约 200~700 毫秒，且只在后台判定路径上异步跑，
    不挡你的正常回复。

  6.3 有显卡想更快（可选）
  ----------------------------------------------------------------
  本包默认带的是 **CPU 版**运行时（谁都能跑）。
  要用显卡加速：把 CUDA 版运行时放进 runtime/llama-cuda/，
  再把设置里"本地模型文件"上面的运行时路径指到
  runtime/llama-cuda/llama-server.exe，并把 gpuLayers 调大
  （99 = 全部层上显卡），重启程序即可。
  CUDA 版约 1.1GB，需要 NVIDIA 显卡 + 驱动。

  6.3b 界面卡不卡跟它无关（2026-09-22 改动）
  ----------------------------------------------------------------
  界面流畅度看的是**桌面端有没有走显卡渲染**，跟这个 0.8B 无关：
  · 现在**默认就走显卡渲染**（毛玻璃、机甲特效都留着）；
  · 极个别老显卡会黑屏/花屏 —— 那就设环境变量 QQ_AGENT_GPU=0 回到软件渲染，
    界面会朴素一点但一定能用（见附录 C）。

  6.4 采信阈值怎么理解
  ----------------------------------------------------------------
  两个门槛一起看：
    minConfidence（默认 0.6）  模型对这个标签有多确信
    minMargin    （默认 1.0）  和"第二可能"的差距有多大
  两个都过才采信；不过就弃权（回退到词表，或直接放行 / 否决）。
  0.8B 的概率绝对值不太可靠，但"和次选的差距"更可靠，所以 margin 很关键。
  · 想让本地管更多事：把两个阈值调低（但判错会变多）
  · 想更稳：调高（更多事情交给云端，费钱）
  调之前先用【4.8】里的「试判」跑几把，再决定往哪边挪。


================================================================
  七、花多少钱：用量与成本
================================================================

  7.1 钱花在哪
  ----------------------------------------------------------------
  一句话：**几乎全花在"主模型的每一轮对话"上**。
  本地小模型的判定是 0 成本，云端小额裁判占比极低。

  真正贵的是这两件事：
    ① 每轮要重新送进去的上下文（历史 + 记忆 + 工具定义）
    ② 它一轮没说完、又跑了一轮（多一轮 = 再付一次全部输入）

  7.2 四个省钱开关（按性价比排序）
  ----------------------------------------------------------------
  1) 缓存（最值）
     「设置 → 模型 API → 上下文缓存模式」选「自适应 + 保温」。
     原理：把"永远不变的大块"（工具定义 + 人设 + 静态说明，
     约 1.4 万 token）打上缓存标记，**5 分钟内重复请求只按 10% 计价**。
     注意：标记块是"全有或全无"，动了里面任何一点都会重新计费。
     顶栏「今日」胶囊能看到缓存命中情况与保温发了几棒。

  2) 响应档位（上下文读多少）
     「设置 → 聊天与节奏 → 响应档位」从 4 档降到 2~3 档，
     群里的历史就少读很多（这也是"要不要开口"的总闸）。

  3) 别让它多跑一轮
     「模型 API → 自动收尾」默认开着，话说完就结束，
     不需要它再多说一句"我讲完了"。

  4) 关掉用不上的东西
     · 工具页取消勾选不用的工具（少一个工具 = 少一段 tool 定义）
     · 「模型 API → 架构增强」里的跨轮 / 语义卡 / 跨群（默认就是关的，
       如果你打开过又觉得贵，关掉立刻少注入）
     · 表情包列表张数调小、搜索条数与抓网页上限调小
     · 搜索服务总开关关掉（如果基本不用它搜网）

  7.3 用量页怎么读
  ----------------------------------------------------------------
  · 今日 / 7 天 / 30 天 / 全部 切换
  · 卡片：估算成本、调用次数、搜索次数、输入 token 等
  · 点某一行可以下钻到明细（哪天、哪个会话花得多）
  · 数据来自 data/usage-ledger.ndjson（纯本地，不上传）

  7.4 兜底
  ----------------------------------------------------------------
  「模型 API → 成本护栏」默认开：本地累计 prompt 触顶后，
  会砍掉可选注入（不调模型、不打断主流程）。
  当前上限在用量页顶部能看到。


================================================================
  八、多开：同时跑两个 QQ 号
================================================================

  两个号 = 一份程序 + 两个核心（号A / 号B）+ 各自的数据目录 + 各自连自己的 OneBot 端口。

  · 最省事：双击根目录的「启动-双号.bat」。它**只开一个程序窗口**：
    号A 正常起窗口，号B 由桌面壳作为**无窗口的独立核心**拉起来，
    顶栏出现**账号标签**，点一下就在两个号之间切（这就是"合并"）。
        号A → data\（控制台 3210 起）
        号B → data-2\（控制台按它自己配置里的端口，本地小模型 18090、视觉 18095）
    第一次点它会自动生成 data-2\config.json（从号A 的配置里抄模型/搜索/记忆等，
    **白名单留空** —— 号B 默认谁都不理，去它的控制台把群加上）。
  · ⚠️ 号B 要在 SnowLuma 里**自己有一套 OneBot 网络**（例如 HTTP 3010 / WS 3011）
    并绑到号B，否则号B连不上（它的顶栏圆点是红的）。
    号A 用 SnowLuma 默认的那套（HTTP 3000 / WS 3001）。
  · 稳妥兜底：万一号B 的核心 12 秒内没起来（端口被占、配置坏了……），
    脚本会**自动改成再开一个窗口**跑号B —— 不会让你"点了双号什么都没发生"。
    两种情况都写在 `launch-log.txt` 里，出问题先看它。
  · ⚠️ 号A 已经在跑时再点双号：脚本会识别出来并**不再重复拉起**
    （以前那种"点了没反应"就是因为新号A 撞上实例锁立刻退出了）。
    想合并成一个窗口，先把号A 退干净再点双号。
  · 只用一个号的人：点「启动-单号.bat」。它**只**起号A —— 就算你以前配过 data-2，
    单号脚本也不会把号B 带起来（要两个号就点双号）。
  · 手动等价做法（想自己控制时）：双击「启动-单号.bat」起号A；
    另开一个 cmd 执行 set QQ_AGENT_PROFILE=2 && npm start（这会**再开一个窗口**，
    与上面的"一个窗口两个号"是两种玩法，别同时用）。
  · 两个号的群白名单**别重叠**，否则同一个群会被两个机器人各回一遍。
  · 数据隔离靠环境变量：QQ_AGENT_PROFILE=2 → 数据目录 data-2、端口整体偏移；
    QQ_AGENT_PORT=3220 可以单独指定控制台端口。
  · 一个 QQ 号只能接一个实例；同一个数据目录重复启动会被
    data/instance.lock 挡住并提示"已在运行"。
  · SnowLuma 只有一份就够（它支持多账号，每个号各自一套 OneBot 网络），
    两个号都在它的网页控制台里管理。前提是**两个 QQ 客户端同时在线**。
  · 桌面端启动时会自动把第二个核心拉起来（需要 data-2\config.json 已存在 ——
    用双号脚本跑过一次就会生成），顶栏会出现账号标签页，
    点一下就能切换到那个号的会话 / 记忆 / 用量 / 设置。
    不想自动拉：配置文件里 server.autoStartPeer = false。

  9.2 备份
  ----------------------------------------------------------------

  （SnowLuma 里重新登一次，OneBot 端口对得上就行）。

  9.4 想清空重来
  ----------------------------------------------------------------
  关掉程序，把 data/ 改名备份（别直接删），再启动 = 全新开始。


================================================================
  十、常见问题（排障）
================================================================

  1) 群里 @ 它，它不回
     按顺序查：
       · 顶栏 OneBot 是绿点吗？不是 → 协议端没连上（看「QQ 连接」页日志）
       · 这个群在「聊天白名单」里吗？
       · 顶栏是不是显示「已暂停」？
       · 群里它是不是被禁言了？（ban-state 扩展会直接跳过这一轮）
       · 「会话」页有没有出现这个群？有的话点进去看它这一轮干了什么：
         通常是模型 API 报错（Key 过期 / 余额不足），错误就写在里面。
       · 响应档位太低 + 没 @ 到它 → 它可能压根没被唤醒（这是设计）。

  2) 启动时提示"已在运行（pid=…）"
     上次没退干净，或者真有一份在跑。
       · 真有：点提示里的控制台地址去看看。
       · 没有：删掉 data/instance.lock 再启动。
       · 第二个实例被挡：删它自己 data-2/instance.lock。

  3) 双击没反应 / 窗口一闪而过
     用「启动-单号-调试模式.bat」启动，它会保留控制台窗口和报错。
     常见原因：杀毒软件拦了、路径里有奇怪的字符、
     或者 node_modules 没解压完整（重新完整解压一次）。

  4) 控制台地址打不开
     端口被别人占了。程序会自动往后找端口，真实地址打印在启动窗口里
     （一般是 3210，被占就是 3211、3212……）。

  5) 浏览器能开控制台，但页面一片空白
     换个浏览器（新版 Chrome / Edge），或者 Ctrl+F5 强刷。

  6) 语音消息它只回一句 [语音]
     [语音] 是没转写成功时的占位。要它听懂语音：
     工具页打开「语音转文字」扩展，并自己装好 whisper 与本机模型
     （默认关，属于可选依赖）。

  7) 它发的图片 / 表情很少
     · 工具页确认 send_sticker / send_image 是勾选状态
     · 表情库是不是空的（它会自己收藏，需要时间）
     · 「聊天与节奏 → 发表情积极程度」调高一点

  7b) 表情"有的能发出来、有的发不出来"
     这不是你网络的问题，也不是它坏了 —— 是**表情图源**的三件事：
     · QQ 收藏表情给的是**一小时就过期**的临时链接（rkey），
       前几天同步下来的那张今天就是发不出去（同一批表情里"有的行有的不行"就是这么来的）。
       程序现在会把取到过的表情字节**缓存在本机**
       （data/sticker-images/cache/，上限 500 张，超了自动删最久没用过的），
       所以只要这张表情成功发过一次，以后链接过期也照样能发。
     · 图片是内联在请求体里发给协议端的，图一大（几 MB）协议端会直接掐断连接，
       表现就是报一个 ECONNRESET。程序现在改成：协议端在本机时给它**文件路径**
       （请求体只剩几百字节），并且被掐断会自动换一条连接重试一次。
     · 实在发不出去的那张，让它用 list_stickers 换一张；
       老是那几张不行，就「聊天与节奏 → 给没备注的表情补描述」补一轮，
       再让它重新收藏一次（让群友把图重发进群，它自己会收）。
     查到底哪张坏了：控制台日志里搜 `[sticker]`，
     会写明是"链接过期 / 图源被删 / 取图超时 / 连不上图片服务器"里的哪一种。

  8) 它开始重复同一句话 / 变傻了
     · 上下文被顶上来的垃圾记忆挤掉了 → 去「记忆」页把错的印象删掉
     · 语义卡太多 → 「每轮注入语义卡数」调到 1~2
     · 换了模型 / 提示词后没热重载 → 点一次「更多 ··· → 热重载」

  9) 花销突然变高
     · 用量页下钻看是哪天 / 哪个会话
     · 检查缓存是不是掉了（顶栏「今日」的命中率）
     · 是不是某个群特别活跃、把它频繁唤醒（把那个群的单独档位调低）

 10) 本地小模型显示"未就绪 / 未启动"
     · 点顶栏「小模型」胶囊重新拉起；或去设置页点「重启本地模型」
     · 端口 18080 被别的程序占了 → 设置里换一个端口
     · 它只是没起来，不影响主流程（判定自动回退到词表 / 云端）

 11) 想让它少说话 / 只回答不插嘴
     · 「设置 → 聊天与节奏 → 响应档位」调到 1 档（只有 @ 才读历史、才回应）
     · 同一页的「本地 Jev → 插话判定」把每小时上限压下、冷却拉长
       （注：「主动开话题」这个功能默认就是关的，当前版本界面里没有开关，
        想彻底关掉可以改配置文件里的 proactive.enabled = false）
     · 白名单里只留必须的群

 12) 想彻底静音一段时间
     顶栏「暂停」。横幅里可以「恢复」，也可以「恢复并全部标为已读」
     （暂停期间积压的消息不再处理）。数据不会丢。

 13) 想让它别转发 B 站视频 / 别发表情 / 别搜网
     去「工具」页把对应工具取消勾选（send_bilibili / send_sticker /
     web_search …），或在「设置 → 搜索服务」关掉联网搜索总开关。

 14) 点「启动 SnowLuma」没反应 / 那个 launcher.bat 报
     「'node' 不是内部或外部命令」
     · 从控制台「QQ 连接」页启动 —— 它用的是包内自带的 node.exe，
       不需要你装 Node.js（那个 launcher.bat 才需要）。
     · 网页控制台打不开：它默认在 127.0.0.1:5099，地址就写在"运行日志"里。
     · 忘了它的管理员密码：那是它首次启动时随机生成的、只打印一次；
       关掉它再启动会重新生成一个（密码没改过的情况下）。

================================================================
  十二、二次开发：写一个插件 / 技能
================================================================

  12.1 两种扩展，怎么选
  ----------------------------------------------------------------
    插件 plugins/<id>/  规则能写死时用。给一致性保障，必然执行，
                        不经过模型判断（例：被禁言就不发消息）。
    技能 skills/<id>/   需要模型理解人话时用。注册工具，
                        模型自己决定何时调用。

  12.2 目录与清单
  ----------------------------------------------------------------
    plugins/<id>/plugin.json    { id, name, version, apiVersion: 1,
                                  category, description, settings,
                                  configSchema, capabilities, requires,
                                  prompt, hooks }
    plugins/<id>/index.js       export function setup(api) { ... }
    plugins/<id>/panel.html     可选：插件自带面板
                                （控制台「扩展」详情里会多一个打开按钮）

    skills/<id>/skill.json      { id, name, version, entry, tools: [...],
                                  prompt: { when, examples, instruction },
                                  permissions }
    skills/<id>/index.js        export function setup(api) {
                                  api.registerTool({ id, name, description,
                                                     parameters, execute })
                                }
                                注册出的工具名是 <skillId>__<toolId>

  12.3 能用的能力（api）—— **以这一节为准**
  ----------------------------------------------------------------
  ⚠️ 2026-09-22 更正：本节以前写的是 `api.provide()` / `api.hook()` /
  `api.promptSection()` / `api.config`（当属性用）——**这几个在 0.4 和本版里都不存在**，
  照着写会直接加载失败（`api.provide is not a function`）。
  真实接口如下（与本程序 `src/plugin-loader.js`、0.4 版逐字段一致）：

    提供能力 / 挂钩子 / 加提示词段：**用模块导出**，不是 api 方法
      export const providers = { 'chat.ban-state': (args) => ... }
      export const hooks = {
        'before-llm-messages': ({ messages, chatKey }) => { ... },
        'before-tool':         ({ toolName, argsRaw, chatKey }) => ({ block: true, reason }) ,
        'after-response':      ({ response, chatKey }) => { ... }
      }
      export const promptSections = (ctx) => '要追加的提示词段落'

    生命周期（同样是模块导出，可选）
      export function activate(ctx) { ... }     // 定时器/监听在这里起
      export function deactivate(ctx) { ... }   // 开关关掉/重载时停
      export function available() { return { ok: true, reason: '' } }

    setup(api) 里能用的（这才是 api 对象上的东西）
      api.registerTool(def)        注册工具（技能）。def 里带 execute(ctx, args)，
                                   返回 { content, isError? }
      api.config()                 **函数**：读这个扩展自己的配置（settings 的当前值）
      api.capability(名称, 参数)   软依赖：问"谁提供了这个能力"，有就调、没有返回 undefined
      api.hasCapability(名称)      只问有没有，不调用
      api.isSkillActive(id)        另一个扩展现在是开是关
      api.log / warn / error       日志（会带 [skill:<id>] 前缀）
      api.fetch                    只有清单里声明了 permissions: ["web_fetch"] 才给
      api.utils                     { sleep, safeJsonParse }

  注意：只有 api.registerTool 注册的工具会进模型的工具列表；
  只导出 providers / hooks 的模块放进 skills/ 对模型是完全隐形的
  （加载器会对这种"放错目录"直接告警）。

  12.4 配置表单不用你写
  ----------------------------------------------------------------
  清单里写 configSchema，控制台会**按类型自动生成表单**：
    boolean  → 开关          number   → 数字（可带 min/max/step）
    enum     → 下拉          textarea → 多行文本
    secret   → 密码框（留空 = 不改）      internal → 只读展示
  字段间联动显隐用 showIf。改完在「工具」页点开这个扩展就是表单。

  12.5 生效方式
  ----------------------------------------------------------------
  · 把目录放进 plugins/ 或 skills/，在「工具」页打开开关即可。
  · 改了代码：点顶栏「更多 ···」→ 热重载。
    （改到核心模块如 llm.js / tools.js，需要完全退出程序再启动。）
  · 加载失败会在「工具」页标红并给出错误原因；
    声明了能力却没注册、或把插件放进 skills/ 这类问题也会告警。

  12.6 调试建议
  ----------------------------------------------------------------
  · 先用小脚本直接跑你的处理函数，别一上来就接 QQ。
  · 用「会话」页看工具到底有没有被调用、参数是什么。
  · 想验证扩展能不能加载：命令行跑
        node test/extensions-load-test.mjs
    它会列出每个扩展的加载结果、注册的工具、以及"能力有没有人消费"。
